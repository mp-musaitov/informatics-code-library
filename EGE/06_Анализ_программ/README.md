# №6. Анализ программ и исполнитель Черепаха

## Что проверяет задание

Задание №6 относится к анализу результатов работы простейших алгоритмов управления исполнителями и вычислительных алгоритмов.

В актуальных вариантах особенно часто встречается **исполнитель Черепаха**: нужно понять, какую фигуру построит алгоритм, а затем найти количество точек с целочисленными координатами внутри, на границе, в пересечении или объединении фигур.

Главная идея: сначала понять **геометрию движения**, а уже потом считать точки.

---

# Основной принцип

Алгоритм Черепахи нужно переводить из команд в геометрическую фигуру.

Например:

```text
Повтори 4 [Вперёд 10 Направо 90]
```

Черепаха строит квадрат со стороной 10.

Если после этого хвост поднимается и Черепаха перемещается в другую точку, следующая фигура строится уже относительно нового положения.

Поэтому решение удобно делить на два этапа:

```text
1. Определить, какие фигуры строятся и где они расположены.
2. Посчитать нужные целочисленные точки.
```

---

# Основной способ — геометрический анализ

Для простых прямоугольников, квадратов и их пересечений программа обычно не нужна.

## Шаг 1. Определяем начальное положение

Обычно Черепаха начинает в точке:

```text
(0, 0)
```

и смотрит вверх — вдоль положительного направления оси `Oy`.

## Шаг 2. Последовательно выполняем команды

Основные команды:

```text
Вперёд n
Назад n
Направо m
Налево m
Поднять хвост
Опустить хвост
```

Важно различать:

- перемещение Черепахи;
- изменение направления;
- рисование линии.

Если хвост поднят, Черепаха перемещается, но линия не рисуется.

## Шаг 3. Находим координаты вершин

Для поворотов на 90° удобно вести координаты вручную.

Например, Черепаха смотрит вверх и выполняет:

```text
Вперёд 5
Направо 90
Вперёд 8
```

Получаем:

```text
(0, 0) → (0, 5) → (8, 5)
```

## Шаг 4. Определяем требуемую область

В условии могут спрашивать точки:

- строго внутри фигуры;
- внутри вместе с границей;
- в пересечении нескольких фигур;
- в объединении фигур.

Это принципиально разные случаи.

---

# Подсчёт целочисленных точек в прямоугольнике

Пусть прямоугольник ограничен координатами:

```text
x1 ≤ x ≤ x2
y1 ≤ y ≤ y2
```

## Если граница учитывается

Количество целых значений `x`:

```text
x2 - x1 + 1
```

Количество целых значений `y`:

```text
y2 - y1 + 1
```

Всего точек:

```text
(x2 - x1 + 1) * (y2 - y1 + 1)
```

## Если нужны только внутренние точки

Границы исключаем:

```text
(x2 - x1 - 1) * (y2 - y1 - 1)
```

если вершины прямоугольника имеют целочисленные координаты.

---

# Пересечение прямоугольников

Если фигуры — прямоугольники со сторонами, параллельными осям, пересечение удобно находить по координатам.

Для первого прямоугольника:

```text
[x1, x2] × [y1, y2]
```

Для второго:

```text
[x3, x4] × [y3, y4]
```

Границы пересечения:

```python
left = max(x1, x3)
right = min(x2, x4)
bottom = max(y1, y3)
top = min(y2, y4)
```

После этого остаётся посчитать целочисленные точки внутри найденной области.

# Альтернативный способ №1 — моделирование координат в Python

Если фигур несколько, есть пересечения или движение трудно проследить вручную, можно смоделировать координаты Черепахи программой.

Смысл моделирования: программа **не обязана рисовать фигуру**. Она просто хранит текущее положение Черепахи и направление движения.

Для поворотов, кратных 90°, удобно хранить направление числом:

```text
0 — вверх
1 — вправо
2 — вниз
3 — влево
```

Пример:

```python
x = 0
y = 0
direction = 0


def forward(n):
    global x, y

    if direction == 0:
        y += n
    elif direction == 1:
        x += n
    elif direction == 2:
        y -= n
    else:
        x -= n


def right():
    global direction
    direction = (direction + 1) % 4


for _ in range(4):
    forward(10)
    print(x, y)
    right()
```

Такой код последовательно повторяет команды исполнителя и обновляет его состояние.

Моделирование особенно полезно, если команд много и легко потерять текущую точку или направление.

Для простой фигуры с поворотами на 90° ручной анализ обычно быстрее.

# Альтернативный способ №2 — визуализация с координатной сеткой

Обычная картинка, нарисованная через `turtle`, сама по себе часто мало полезна.

Если просто вывести фигуру на белом фоне, по ней нельзя понять, сколько внутри точек с целочисленными координатами: одинаково выглядящие на экране квадраты могут соответствовать, например, размерам `2 × 2` и `20 × 20`.

Поэтому полезная визуализация должна показывать не только фигуру, но и **масштаб и целочисленные точки**.

## Масштаб

Пусть:

```python
k = 20
```

означает:

```text
1 координатная единица = 20 пикселей на экране
```

Тогда команда:

```text
Вперёд 5
```

в программе записывается как:

```python
forward(5 * k)
```

При этом математически Черепаха прошла именно 5 единиц.

## Пример визуализации

```python
from turtle import *

tracer(0)

k = 20

# Черепаха по условию смотрит вверх
left(90)

# Рисуем квадрат со стороной 5
for _ in range(4):
    forward(5 * k)
    right(90)

# Рисуем точки с целочисленными координатами
penup()

for x in range(-1, 7):
    for y in range(-1, 7):
        goto(x * k, y * k)
        dot(4)

update()
done()
```

Теперь на рисунке видна не только граница фигуры, но и сетка целочисленных точек.

Такой способ уже можно использовать для реальной проверки ответа.

## Почему нужен масштаб

Без масштаба соседние целочисленные точки находились бы всего в одном пикселе друг от друга и сливались бы.

Масштаб растягивает рисунок, но не меняет математические координаты.

Например:

```python
goto(3 * k, 2 * k)
```

на экране означает точку:

```text
(3, 2)
```

а не `(60, 40)`.

# Как понять, какой способ выбрать

**Геометрический анализ** — основной способ, если фигура легко распознаётся: квадрат, прямоугольник, несколько простых фигур, повороты на 90°.

**Моделирование координат в Python** — полезно, если команд много и легко ошибиться в текущем положении или направлении.

**Визуализация с целочисленными точками** — полезна для проверки сложной геометрии, особенно если есть наклонные стороны, необычные повороты или трудно понять расположение точек относительно границы.

Просто нарисовать контур без координатной сетки обычно недостаточно.

---

# Пример

Пусть алгоритм:

```text
Повтори 4 [Вперёд 6 Направо 90]
```

Черепаха строит квадрат со стороной 6.

Если требуется количество точек с целочисленными координатами **строго внутри**, то по каждой координате допустимы значения:

```text
1, 2, 3, 4, 5
```

То есть:

```text
5 * 5 = 25
```

Ответ:

```text
25
```

Если бы граница учитывалась, было бы:

```text
7 * 7 = 49
```

# Частые ошибки

## 1. Забыть начальное направление

Черепаха обычно смотрит вверх, а не вправо.

## 2. Считать, что поднятый хвост останавливает движение

Нет. Черепаха продолжает двигаться, просто не рисует линию.

## 3. Перепутать направление поворота

```text
Направо — по часовой стрелке
Налево — против часовой стрелки
```

## 4. Неправильно раскрыть `Повтори`

Нужно повторять **всю последовательность команд внутри скобок**.

## 5. Перепутать «внутри» и «внутри вместе с границей»

Одна фраза в условии меняет количество точек.

## 6. Считать площадь вместо количества точек

Площадь фигуры и число целочисленных точек — разные величины.

## 7. При пересечении считать каждую фигуру отдельно

Нужно сначала найти именно общую область, а затем считать точки в ней.

## 8. Использовать визуализацию без масштаба и целочисленных точек

Контур фигуры показывает форму, но не даёт надёжного способа посчитать точки.

# Быстрая памятка

```text
1. Зафиксируй начальную точку и направление.
2. Выполни алгоритм по шагам.
3. Найди координаты вершин фигур.
4. Учти перемещения с поднятым хвостом.
5. Определи: внутри, граница, пересечение или объединение.
6. Найди границы нужной области.
7. Посчитай целочисленные координаты.
8. Для простой геометрии решай вручную.
9. Если команд много — моделируй координаты в Python.
10. Если нужна картинка — рисуй не только фигуру, но и целочисленные точки.
```

---

Главный навык в №6 — не «запустить Черепаху», а **перевести алгоритм движения в понятную геометрическую модель**.
