# №4. Кодирование и условие Фано

## Что проверяет задание

В задании №4 нужно работать с **неравномерными двоичными кодами** и понимать, когда сообщение можно однозначно декодировать.

Обычно требуется:

- подобрать код для нового символа;
- подобрать несколько новых кодов;
- найти минимально возможную длину кода;
- определить подходящее кодовое слово;
- проверить условие Фано;
- выбрать вариант, при котором код остаётся однозначно декодируемым.

Главная идея: кодовые слова должны быть устроены так, чтобы при чтении последовательности битов было понятно, **где заканчивается один символ и начинается другой**.

---

## Основной принцип

Для однозначного декодирования часто используется **условие Фано**.

### Прямое условие Фано

Ни одно кодовое слово не должно быть **началом другого кодового слова**.

Например:

```text
A = 0
B = 10
C = 110
D = 111
```

Такой набор удовлетворяет прямому условию Фано.

А вот набор

```text
A = 0
B = 01
```

не подходит, потому что код `0` является началом кода `01`.

### Обратное условие Фано

Иногда в условии используется обратное условие Фано:

> ни одно кодовое слово не должно быть **окончанием другого кодового слова**.

В этом случае нужно сравнивать не начала, а концы кодов.

---

# Основной способ — логический подбор

Для большинства заданий №4 ручное решение быстрее программы.

## Шаг 1. Выпишите все известные кодовые слова

Например:

```text
А — 00
Б — 01
В — 10
```

Нужно подобрать код для буквы Г.

## Шаг 2. Определите, какие короткие коды запрещены

Если используем прямое условие Фано, нельзя брать код, который:

1. сам является началом уже существующего кода;
2. имеет своим началом одно из уже существующих кодовых слов.

Для набора

```text
00
01
10
```

одноразрядные варианты:

```text
0
1
```

не подходят:

- `0` является началом `00` и `01`;
- `1` является началом `10`.

Проверяем двоичные коды длины 2:

```text
00
01
10
11
```

Первые три уже заняты, а `11` подходит.

Ответ:

```text
11
```

# Как искать код минимальной длины

Если требуется найти **кратчайший возможный код**, перебирайте длины по порядку:

```text
1 бит
2 бита
3 бита
4 бита
...
```

Для длины 1:

```text
0
1
```

Для длины 2:

```text
00
01
10
11
```

Для длины 3:

```text
000
001
010
011
100
101
110
111
```

Как только найден допустимый вариант, более длинные коды уже не нужны, если задача спрашивает именно минимальную длину.

# Быстрый способ — дерево кодов

Неравномерный префиксный код удобно представлять в виде двоичного дерева.

```text
        начало
        /    \
       0      1
      / \    / \
     00 01  10 11
```

Если некоторый узел уже является кодовым словом, то при прямом условии Фано **нельзя использовать его потомков**.

Например, если код `0` уже занят, то запрещены:

```text
00
01
000
001
010
011
...
```

Это позволяет быстро видеть свободные ветви без полного перебора.

# Альтернативный способ — Python

На экзамене кандидат обычно легко проверяется вручную. Программа полезна прежде всего как формальная проверка и как универсальный перебор, если хочется автоматически найти допустимые коды.

## Проверка готового набора

В списке `codes` хранятся **все коды, которые уже заданы в условии**.

```python
def fano(codes):
    for a in codes:
        for b in codes:
            if a != b and b.startswith(a):
                return False
    return True


codes = ['00', '01', '10']
print(fano(codes))
```

Если хотим проверить новый кандидат, временно добавляем его к исходным кодам:

```python
new_code = '11'
print(fano(codes + [new_code]))
```

Если получаем `True`, весь набор удовлетворяет прямому условию Фано.

---

# Поиск кратчайшего кода программой

Можно сохранить простую логику:

```text
исходные коды → новый двоичный код → проверка Фано
```

Но обычный вызов

```python
bin(n)[2:]
```

не перебирает коды с ведущими нулями. Например, двоичная запись числа `1` — это `1`, а не `01` или `001`.

Поэтому сначала перебираем **длину кодового слова**, а затем все числа, которые помещаются в такое количество битов.

```python
def fano(codes):
    for a in codes:
        for b in codes:
            if a != b and b.startswith(a):
                return False
    return True


codes = ['00', '01', '10']

for length in range(1, 10):
    for n in range(2 ** length):
        new_code = bin(n)[2:].zfill(length)

        if new_code not in codes and fano(codes + [new_code]):
            print(new_code)
            raise SystemExit
```

Программа выведет:

```text
11
```

## Что происходит в переборе

При `length = 1`:

```text
0
1
```

При `length = 2`:

```text
00
01
10
11
```

При `length = 3`:

```text
000
001
010
011
100
101
110
111
```

Строка

```python
new_code = bin(n)[2:].zfill(length)
```

делает две вещи:

```python
bin(n)[2:]
```

переводит число в двоичную систему, а

```python
.zfill(length)
```

добавляет ведущие нули до нужной длины.

Например:

```python
bin(1)[2:]          # '1'
bin(1)[2:].zfill(2) # '01'
bin(1)[2:].zfill(3) # '001'
```

Так мы действительно перебираем **все двоичные кодовые слова каждой длины**.

Поскольку длины проверяются от меньших к большим, первый найденный код гарантированно имеет минимальную длину.

# Если нужно подобрать несколько кодов

Если в задании требуется подобрать не один, а несколько новых кодов, после нахождения подходящего варианта его можно **добавить в список `codes`**. Тогда следующий кандидат будет проверяться уже не только с исходными кодами, но и со всеми кодами, найденными ранее.

Например, пусть известны два кода, а всего нужно получить четыре кодовых слова:

```python
def fano(codes):
    for a in codes:
        for b in codes:
            if a != b and b.startswith(a):
                return False
    return True


codes = ['00', '01']
total = 4

for length in range(1, 10):
    for n in range(2 ** length):
        new_code = bin(n)[2:].zfill(length)

        if new_code not in codes and fano(codes + [new_code]):
            codes.append(new_code)

            if len(codes) == total:
                break

    if len(codes) == total:
        break

print(codes)
```

Результат:

```text
['00', '01', '10', '11']
```

Логика программы:

```text
1. Берём исходные коды.
2. Перебираем возможные новые коды от коротких к длинным.
3. Проверяем кандидат вместе со всем текущим набором.
4. Если условие Фано выполняется — добавляем кандидат в codes.
5. Следующий кандидат проверяется уже с обновлённым набором.
6. Когда len(codes) становится равен общему количеству необходимых кодов, останавливаем перебор.
```

Важно: `total` — это **общее количество кодовых слов**, которое должно получиться, а не количество новых кодов.

Такой последовательный подбор хорошо подходит, если требуется просто построить допустимый набор. Если в условии требуется **оптимизировать сразу несколько новых кодов** (например, получить наилучший набор по дополнительному критерию), простой жадный подбор первого подходящего варианта не всегда гарантирует оптимальный результат.

# Обратное условие Фано

Если в условии прямо сказано, что используется **обратное условие Фано**, проверяем окончания строк.

```python
def reverse_fano(codes):
    for a in codes:
        for b in codes:
            if a != b and b.endswith(a):
                return False
    return True
```

Не путайте:

```python
startswith()   # начинается с
endswith()     # заканчивается на
```

# Когда какой способ удобнее

## Ручной способ удобнее, если

- известных кодов немного;
- нужно добавить один код;
- видно свободную ветвь дерева;
- требуется минимальная длина и ответ находится среди коротких кодов.

## Python удобнее, если

- кодовых слов много;
- нужно формально проверить готовый набор;
- нужно последовательно подобрать несколько кодов;
- хочется автоматически перебрать все варианты по длине;
- ручная проверка легко приводит к пропуску конфликта.

На экзамене основной способ для №4 — **логический подбор**, а программа остаётся полезной альтернативой и проверкой.

# Частые ошибки

## 1. Проверять только совпадение кодов

Недостаточно убедиться, что кодовые слова различны.

```text
0
01
```

Слова разные, но условие Фано нарушено.

## 2. Проверять только одну пару

Новый код нужно сравнить **со всеми исходными и уже найденными кодами**.

## 3. Перепутать прямое и обратное условие Фано

Прямое:

```text
начала кодовых слов
```

Обратное:

```text
окончания кодовых слов
```

## 4. Сразу подбирать длинный код

Если требуется минимальная длина, сначала проверяются все более короткие варианты.

## 5. Использовать занятый код повторно

Два разных символа не могут иметь одно и то же кодовое слово.

## 6. Перебирать только `bin(n)[2:]`

Так будут потеряны варианты с ведущими нулями:

```text
00
01
001
010
...
```

Если нужен полный перебор кодов заданной длины, используйте `.zfill(length)`.

## 7. При подборе нескольких кодов не добавлять найденный код в список

Если найденный код не добавить в `codes`, следующий кандидат не будет проверяться относительно него.

---

# Быстрая памятка

```text
1. Определи: прямое или обратное условие Фано.
2. Выпиши все исходные кодовые слова.
3. Если нужна минимальная длина — начинай с самых коротких кодов.
4. Для прямого Фано сравнивай начала строк.
5. Для обратного Фано сравнивай окончания строк.
6. Новый код проверь со ВСЕМИ кодами текущего набора.
7. В программе перебирай сначала длину, затем все 2^length вариантов.
8. Для ведущих нулей используй zfill().
9. Если найденный код нужен дальше — добавь его в codes.
10. Если кодов стало столько, сколько требуется, останови перебор.
```

## Мини-шпаргалка Python

```python
b.startswith(a)       # начинается ли b с a
b.endswith(a)         # заканчивается ли b на a
bin(n)[2:]             # двоичная запись числа
bin(n)[2:].zfill(k)    # двоичная запись длины k с ведущими нулями
codes.append(code)     # добавить найденный код в набор
len(codes)             # количество кодов в текущем наборе
```

Главная идея задания №4: **сначала понять логику допустимого кода, а программный перебор использовать как универсальную проверку или альтернативный способ**.
