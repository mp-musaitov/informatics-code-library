# ЕГЭ №12. Машина Тьюринга

## Что проверяет задание

В актуальной модели задания №12 основной тип — **машина Тьюринга**. Именно она представлена в демонстрационной версии ЕГЭ-2027, как и в демоверсии 2026 года.

В задаче дана:

- бесконечная лента, разбитая на ячейки;
- последовательность символов на ленте;
- положение головки;
- начальное состояние;
- таблица команд машины;
- условие о результате работы.

Нужно понять, **какое преобразование выполняет машина**, и по конечному результату определить требуемое свойство исходной последовательности.

Старый исполнитель **Редактор** тоже полезно знать, поэтому его шаблон сохранён в конце материала как дополнительный тип. Но при подготовке к актуальному №12 в первую очередь стоит научиться читать таблицу переходов машины Тьюринга.

---

# 1. Как устроена машина Тьюринга

Машина состоит из:

```text
лента + головка + состояние + программа
```

Лента разбита на ячейки. В каждой ячейке находится один символ, например:

```text
0 1 1 0 0 1
```

За пределами записанной последовательности находятся пустые ячейки. Обычно они обозначаются:

```text
λ
```

Головка в каждый момент времени находится ровно над одной ячейкой и в одном состоянии:

```text
q0, q1, q2, ...
```

---

# 2. Как читать одну команду

Команда определяется двумя вещами:

```text
текущее состояние + символ под головкой
```

Например, в таблице стоит:

```text
0, L, q2
```

Это означает:

```text
1. записать в текущую ячейку 0;
2. сдвинуть головку на одну ячейку влево;
3. перейти в состояние q2.
```

Обозначения:

```text
L — шаг влево
R — шаг вправо
S — остановиться / не продолжать движение в данной команде
λ — пустая ячейка
```

В конкретном условии всегда ориентируйтесь на обозначения, которые даны в самом задании.

---

# 3. Как читать таблицу переходов

Допустим, дана таблица:

| состояние | λ | 0 | 1 |
|---|---|---|---|
| q0 | λ, L, q1 | — | — |
| q1 | λ, S, q1 | 1, L, q1 | 0, L, q1 |

Если головка находится в состоянии `q1` над символом `0`, берём строку `q1` и столбец `0`:

```text
1, L, q1
```

Значит:

```text
0 → 1
головка → влево
состояние остаётся q1
```

Если под головкой `1`:

```text
0, L, q1
```

то:

```text
1 → 0
головка → влево
состояние остаётся q1
```

Следовательно, уже без полной трассировки видно главное:

> двигаясь справа налево, машина меняет каждый бит на противоположный.

Именно такой **смысл программы** обычно и нужно обнаружить.

---

# Основной принцип решения

Не пытайтесь вручную выполнять сотни шагов машины.

Сначала переведите таблицу переходов с языка команд на обычный русский язык.

Например:

```text
q0: перейти с пустой ячейки на последний символ последовательности;
q1: идти справа налево;
0 превращать в 1;
1 превращать в 0;
на левой пустой ячейке остановиться.
```

Теперь вместо большой таблицы имеем простое описание:

```text
машина инвертирует все биты последовательности
```

После этого задача обычно решается рассуждением или несколькими вычислениями.

# Универсальный алгоритм решения №12

```text
1. Найти начальное положение головки.
2. Посмотреть команду для первого шага.
3. Определить, в каком направлении начинает двигаться машина.
4. Разобрать действия машины над 0, 1 и λ в каждом используемом состоянии.
5. Сформулировать словами, что делает каждый этап алгоритма.
6. Определить общее преобразование последовательности.
7. Только после этого использовать числовые данные из вопроса.
```

Ключевой переход:

```text
таблица команд → смысл алгоритма
```

# Тип 1. Инверсия битов

Очень важный базовый случай:

```text
0 → 1
1 → 0
```

Например:

```text
исходная строка:  001011
результат:        110100
```

Если исходная строка содержит:

```text
x нулей
y единиц
```

то после полной инверсии получится:

```text
y нулей
x единиц
```

Поэтому длинную строку строить вообще не требуется.

---

# Тип 2. Машина проходит последовательность и изменяет количество символов

Иногда машина сначала проходит всю последовательность, а затем выполняет ещё одно действие.

Например:

```text
1. инвертирует все символы;
2. возвращается в другую сторону;
3. находит первый подходящий символ;
4. изменяет его;
5. останавливается.
```

Тогда удобно анализировать преобразование по этапам.

Допустим, было:

```text
x нулей и y единиц
```

После первого этапа:

```text
y нулей и x единиц
```

Если затем ещё один `0` превращается в `1`:

```text
нулей станет y - 1
единиц станет x + 1
```

Так задача на сотни символов превращается в два простых выражения.

---

# Тип 3. Известен результат — нужно восстановить исходные данные

Это один из наиболее естественных типов для машины Тьюринга.

Например, известно:

```text
после работы осталось 125 нулей
```

Сначала выясняем, как программа меняет число нулей.

Если из анализа таблицы получили:

```text
конечное число нулей = исходное число единиц - 1
```

то уже решаем обычное уравнение:

```text
единиц - 1 = 125
единиц = 126
```

Если общая длина последовательности известна, количество нулей находится вычитанием.

---

# Тип 4. Работа с двоичным числом

Последовательность на ленте может рассматриваться как двоичная запись числа.

Тогда после анализа работы машины удобно использовать Python для перевода между системами счисления.

Из десятичной в двоичную:

```python
print(bin(240)[2:])
```

Получим:

```text
11110000
```

Из двоичной в десятичную:

```python
print(int('11110000', 2))
```

Если машина инвертирует биты, можно восстановить исходную последовательность:

```text
результат: 11110000
исходная:  00001111
```

Но обязательно учитывайте условие задачи: ведущие нули на ленте могут быть частью записанной последовательности, хотя в обычной записи числа они не отображаются.

# Ручная трассировка

Если поведение машины не видно сразу, возьмите **маленький пример** и выполните несколько шагов вручную.

Удобно записывать:

```text
лента | позиция головки | состояние
```

Например:

```text
λ 0 1 1 λ | справа | q0
λ 0 1 1 λ | на 1   | q1
λ 0 1 0 λ | на 1   | q1
...
```

На каждом шаге меняются максимум три вещи:

```text
символ
позиция головки
состояние
```

После 3–5 шагов часто становится видно закономерное поведение машины.

Ручная трассировка нужна прежде всего **для понимания закономерности**, а не для обработки всей длинной последовательности.

---

# Как анализировать состояния

Очень удобно дать каждому состоянию словесный смысл.

Например:

```text
q0 — перейти на последний символ
q1 — идти влево и инвертировать
q2 — идти вправо до первого нуля
```

После этого программа читается почти как обычный алгоритм:

```text
перейти к концу → инвертировать строку справа налево → вернуться вправо до нужного символа
```

Это намного понятнее, чем постоянно смотреть на обозначения `q0`, `q1`, `q2`.

# Нужно ли писать симулятор на Python?

Обычно — нет.

В большинстве экзаменационных задач таблица специально устроена так, чтобы её поведение можно было понять логически.

Полноценный симулятор машины Тьюринга может оказаться сложнее самой задачи.

Python полезен уже **после анализа таблицы** для небольших вычислений:

```python
# перевод числа в двоичную систему
s = bin(240)[2:]

# число нулей и единиц
print(s.count('0'))
print(s.count('1'))

# перевод обратно
print(int(s, 2))
```

Если хочется проверить сложную таблицу, симулятор можно написать отдельно, но это скорее инструмент проверки и обучения, чем основной экзаменационный способ.

# Как понять, что делает машина

При чтении таблицы задавайте четыре вопроса:

```text
1. Куда движется головка в этом состоянии?
2. Какие символы она меняет?
3. Какое событие заставляет её сменить состояние?
4. Что означает новое состояние?
```

Например:

```text
q1 идёт только влево;
на 0 пишет 1;
на 1 пишет 0;
при λ переходит в q2.
```

Вывод:

```text
q1 полностью проходит последовательность справа налево,
инвертирует её и после достижения левой границы запускает следующий этап.
```

# Частые ошибки

## 1. Смотреть только на замену символа

Команда содержит не одно, а три действия:

```text
что записать + куда перейти + какое будет состояние
```

## 2. Забывать, что строка таблицы определяется состоянием

Один и тот же символ `0` в состояниях `q1` и `q2` может обрабатываться совершенно по-разному.

## 3. Путать направление движения

```text
L → влево
R → вправо
```

Полезно буквально нарисовать стрелку рядом с состоянием.

## 4. Считать λ обычным символом последовательности

`λ` — пустая ячейка за границей записанной последовательности.

Она часто используется машиной как сигнал:

```text
дошли до края → сменить состояние
```

## 5. Трассировать сотни символов вручную

Если в условии 255, 1000 или несколько тысяч символов, почти наверняка нужно найти закономерность, а не рисовать всю ленту.

## 6. Не учитывать дополнительное действие после основного прохода

Машина может сначала инвертировать всю последовательность, а затем изменить ещё один символ. Нельзя останавливаться после анализа первого этапа.

## 7. Сразу писать большой Python-симулятор

Сначала разберите смысл таблицы. Часто после этого программировать уже нечего.

# Дополнительно: классический исполнитель Редактор

В старых вариантах №12 часто использовался исполнитель **Редактор**. Этот тип всё ещё полезен для тренировки моделирования строковых алгоритмов.

Основные команды:

```text
нашлось(111)
заменить(111, 2)
```

В Python:

```python
'111' in s
s = s.replace('111', '2', 1)
```

Важно: последний аргумент `1` означает заменить только **первое слева** вхождение.

Программа:

```text
ПОКА нашлось(111) ИЛИ нашлось(222)
    ЕСЛИ нашлось(111)
        заменить(111, 2)
    ИНАЧЕ
        заменить(222, 3)
КОНЕЦ ПОКА
```

переводится так:

```python
while '111' in s or '222' in s:
    if '111' in s:
        s = s.replace('111', '2', 1)
    else:
        s = s.replace('222', '3', 1)
```

Полезные операции:

```python
len(s)                 # длина строки
s.count('1')           # количество единиц
sum(map(int, s))       # сумма цифр
```

Для актуальной подготовки этот раздел стоит воспринимать как дополнительный. **Основное внимание в №12 — чтению и анализу программы машины Тьюринга.**
