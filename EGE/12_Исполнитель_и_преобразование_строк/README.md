# ЕГЭ №12. Исполнитель и преобразование строк

## Что проверяет задание

В задании №12 нужно выполнить алгоритм исполнителя над последовательностью символов и определить результат его работы.

В вариантах могут встречаться разные исполнители. Для классического **Редактора** используются команды `заменить` и `нашлось`; в актуальных тренировочных материалах встречаются и задачи с **машиной Тьюринга**, где работа задаётся таблицей состояний.

Поэтому главный навык здесь — не запоминание конкретного исполнителя, а **точное моделирование алгоритма**.

---

# Основной принцип

Любой такой алгоритм нужно читать буквально:

```text
1. определить текущее состояние;
2. проверить условие;
3. выполнить именно ту команду, которую задаёт программа;
4. получить новое состояние;
5. повторять, пока условие выполняется.
```

Самая частая причина ошибки — мысленно выполнить не программу, а «то, что она вроде бы делает».

Если преобразований много, надёжнее перенести алгоритм в Python.

---

# Часть 1. Исполнитель Редактор

## Команда `заменить(v, w)`

Команда заменяет **первое слева** вхождение строки `v` на строку `w`.

Например:

```text
строка:  11122111
команда: заменить(111, 5)
результат: 522111
```

В Python этому соответствует:

```python
s = s.replace('111', '5', 1)
```

Последний аргумент `1` очень важен: он означает заменить только **одно**, первое вхождение.

Без него:

```python
s.replace('111', '5')
```

Python заменит сразу все найденные вхождения, а это уже другая программа.

---

## Команда `нашлось(v)`

Она проверяет, содержится ли строка `v` в текущей строке.

В Python:

```python
'111' in s
```

Например:

```python
if '111' in s:
    ...
```

---

# Цикл ПОКА

Программа вида:

```text
ПОКА нашлось(111)
    заменить(111, 2)
КОНЕЦ ПОКА
```

переводится практически дословно:

```python
while '111' in s:
    s = s.replace('111', '2', 1)
```

Цикл продолжается до тех пор, пока `111` встречается в строке.

---

# Несколько условий

Если программа содержит:

```text
ПОКА нашлось(111) ИЛИ нашлось(222)
```

пишем:

```python
while '111' in s or '222' in s:
```

Если требуется одновременное выполнение условий:

```text
ПОКА нашлось(111) И нашлось(222)
```

то:

```python
while '111' in s and '222' in s:
```

---

# Конструкция ЕСЛИ

Например:

```text
ЕСЛИ нашлось(111)
    ТО заменить(111, 2)
    ИНАЧЕ заменить(222, 3)
КОНЕЦ ЕСЛИ
```

В Python:

```python
if '111' in s:
    s = s.replace('111', '2', 1)
else:
    s = s.replace('222', '3', 1)
```

Здесь важно сохранить структуру исходного алгоритма: `else` выполняется только тогда, когда условие `if` ложно.

---

# Универсальный шаблон Редактора

```python
s = '1' * 50

while '111' in s or '222' in s:
    if '111' in s:
        s = s.replace('111', '2', 1)
    else:
        s = s.replace('222', '3', 1)

print(s)
```

В конкретном задании меняются:

- начальная строка;
- условия цикла;
- правила замены;
- то, что нужно вывести.

---

# Тип 1. Найти итоговую строку

После моделирования достаточно вывести:

```python
print(s)
```

---

# Тип 2. Найти длину итоговой строки

```python
print(len(s))
```

---

# Тип 3. Посчитать символы

Количество единиц:

```python
print(s.count('1'))
```

Количество двоек:

```python
print(s.count('2'))
```

Сумма цифр строки:

```python
print(sum(map(int, s)))
```

# Тип 4. Найти исходное количество символов

Иногда в условии неизвестно, сколько символов было в начальной строке, но известно свойство результата.

Тогда можно перебрать возможное значение `n`:

```python
for n in range(1, 1000):
    s = '1' * n

    while '111' in s:
        s = s.replace('111', '2', 1)

    if s.count('2') == 10:
        print(n)
```

Если требуется минимальное или максимальное значение, важно понимать порядок перебора и условие задачи.

---

# Быстрый способ: анализ изменения количества символов

Не всегда нужно моделировать длинную строку.

Например:

```text
111 → 2
```

одна замена:

- убирает три единицы;
- добавляет одну двойку;
- уменьшает длину строки на 2.

Если замены независимы и их количество легко определить, задачу иногда быстрее решить арифметически.

Но если новые символы создают новые подходящие подстроки, безопаснее использовать Python.

# Часть 2. Машина Тьюринга

В задачах с машиной Тьюринга дана лента, положение головки, начальное состояние и таблица команд.

Команда обычно содержит три части:

```text
новый символ, действие, новое состояние
```

Например:

```text
0, L, q2
```

означает:

```text
1. записать в текущую ячейку 0;
2. перейти на одну ячейку влево;
3. перейти в состояние q2.
```

Обозначения:

```text
L — влево
R — вправо
N — остаться на месте
S — остановиться
λ — пустая ячейка
```

---

# Как анализировать таблицу машины Тьюринга

Не нужно сразу пытаться проследить сотни ячеек.

Сначала выясните, **что делает машина при каждом символе и состоянии**.

Например:

```text
q1 + 0 → записать 1 и идти влево
q1 + 1 → записать 0 и перейти вправо в q2
q2 + 0 → записать 1 и идти вправо
q2 + 1 → записать 1 и идти вправо
```

Из такого описания часто становится видно общее поведение алгоритма:

```text
машина идёт влево до определённого события,
затем разворачивается
и обрабатывает оставшуюся часть строки.
```

После этого можно считать изменения количества нулей и единиц уже математически.

---

# Ручная трассировка машины Тьюринга

Для короткой последовательности удобно выписывать:

```text
лента | позиция головки | состояние
```

Например:

```text
0110λ | 4 | q1
0111λ | 3 | q2
...
```

После каждого шага изменяем строго три вещи:

```text
символ → позицию → состояние
```

Это помогает не потерять переход состояния или направление движения.

---

# Python для машины Тьюринга

Для сложной таблицы можно написать симулятор, но в №12 это не всегда рационально: код самого симулятора может оказаться сложнее ручного анализа.

Принцип модели такой:

```python
# пример идеи, а не универсальная программа для любого задания

tape = list('011010')
pos = 0
state = 'q1'
```

Затем в цикле по текущим `state` и `tape[pos]` выполняется соответствующая команда таблицы.

Практический принцип для экзамена:

```text
сначала понять поведение машины;
симулятор писать только тогда, когда ручная трассировка действительно сложнее.
```

---

# Как понять, какой способ выбрать

**Редактор с длинной цепочкой замен** → обычно Python.

**Редактор с простой заменой и очевидным изменением количества символов** → можно решить арифметически.

**Машина Тьюринга с простым законом работы** → анализ таблицы и рассуждение.

**Машина Тьюринга со сложными переходами** → короткая ручная трассировка на маленьком примере, а при необходимости программное моделирование.

# Частые ошибки

## 1. Заменять все вхождения сразу

Неправильно:

```python
s = s.replace('111', '2')
```

Правильно для команды Редактора:

```python
s = s.replace('111', '2', 1)
```

## 2. Выполнить цикл только один раз

`ПОКА` означает многократное повторение:

```python
while ...:
```

а не:

```python
if ...:
```

## 3. Проверять старую строку

После каждой замены строка меняется. Условие следующего прохода проверяется уже для **новой строки**.

## 4. Перепутать И и ИЛИ

```text
И     → and
ИЛИ   → or
```

## 5. Неправильно построить начальную строку

Если сказано «50 единиц, затем 30 двоек»:

```python
s = '1' * 50 + '2' * 30
```

## 6. В машине Тьюринга забыть сменить состояние

Команда изменяет не только символ и позицию головки. Третий элемент команды задаёт следующее состояние.

## 7. Считать `λ` обычным символом исходной последовательности

`λ` обозначает пустую ячейку ленты и обычно служит границей записанной последовательности.

# Быстрая памятка

```text
РЕДАКТОР

нашлось('111')        → '111' in s
заменить(111, 2)      → s.replace('111', '2', 1)
ПОКА                   → while
ЕСЛИ                   → if
ИНАЧЕ                  → else
длина строки           → len(s)
число символов          → s.count(...)
сумма цифр              → sum(map(int, s))

МАШИНА ТЬЮРИНГА

смотрим: состояние + текущий символ
команда: новый символ + движение + новое состояние
L → влево
R → вправо
N → без движения
S → остановка
λ → пустая ячейка
```

Главный вопрос задания №12:

> **Что именно изменяется после одного шага алгоритма и какое состояние получится после него?**

Если каждый шаг переводить буквально, задача перестаёт быть «магией длинных строк» и превращается в обычное моделирование.
