# №11. Количество информации и пароли

## Что проверяет задание

Задание №11 связано с посимвольным кодированием идентификаторов, паролей, серийных номеров и других записей фиксированной длины.

В проекте демоверсии ЕГЭ-2027 нужно определить максимально возможную мощность алфавита по длине серийного номера, количеству номеров и ограничению на общий объём памяти.

Главная идея задания — правильно выполнить три округления:

1. определить минимальное число бит на один символ;
2. определить минимальное целое число байт на одну запись;
3. учесть количество записей.

---

# Основной принцип

Пусть:

- `N` — мощность алфавита;
- `i` — число бит на один символ;
- `L` — длина пароля или идентификатора;
- `M` — память на одну запись;
- `K` — количество записей.

Тогда минимальное число бит на один символ определяется условием:

```text
2^i >= N
```

или, точнее:

```text
2^(i-1) < N <= 2^i
```

После этого на весь идентификатор требуется:

```text
L * i бит
```

Но в памяти под одну запись отводится **целое число байт**, поэтому нужно округлить вверх:

```text
M = ceil(L * i / 8)
```

И только затем считать общий объём:

```text
M * K
```

Важно: округлять нужно память **для одной записи**, а не общий объём после умножения на количество записей.

---

# Шаг 1. Сколько бит нужно на один символ

Если алфавит содержит `N` разных символов, ищем минимальное `i`, для которого:

```text
2^i >= N
```

Примеры:

```text
N = 2   -> i = 1
N = 3   -> i = 2
N = 4   -> i = 2
N = 5   -> i = 3
N = 8   -> i = 3
N = 9   -> i = 4
N = 26  -> i = 5
N = 62  -> i = 6
```

Удобно запомнить степени двойки:

```text
2^1 = 2
2^2 = 4
2^3 = 8
2^4 = 16
2^5 = 32
2^6 = 64
2^7 = 128
2^8 = 256
```

---

# Шаг 2. Сколько памяти занимает одна запись

Если идентификатор состоит из `L` символов, а каждый символ занимает `i` бит:

```text
I = L * i
```

бит.

Затем переводим в байты и округляем вверх.

Например:

```text
L = 15
N = 26
```

Для 26 символов требуется:

```text
i = 5 бит
```

Тогда:

```text
15 * 5 = 75 бит
```

В байтах:

```text
75 / 8 = 9.375 байта
```

Минимальное целое число байт:

```text
10 байт
```

---

# Как округлять вверх без калькулятора

Для целых чисел удобно использовать формулу:

```text
байт = (бит + 7) // 8
```

Например:

```text
75 бит
(75 + 7) // 8 = 82 // 8 = 10 байт
```

В Python:

```python
bytes_per_item = (bits + 7) // 8
```

Это эквивалентно округлению вверх.

---

# Тип 1. Найти объём памяти

Даны:

- мощность алфавита;
- длина пароля;
- количество пользователей.

Нужно найти общий объём памяти.

## Алгоритм

1. Найти `i` из условия `2^i >= N`.
2. Найти количество бит на одну запись: `L * i`.
3. Перевести в целое число байт с округлением вверх.
4. Умножить на количество записей.

### Пример

Пароль имеет длину 20 символов и использует алфавит из 12 символов.

```text
2^3 = 8 < 12 <= 16 = 2^4
```

Значит:

```text
i = 4
```

На пароль:

```text
20 * 4 = 80 бит = 10 байт
```

Для 1000 пользователей:

```text
10 * 1000 = 10000 байт
```

---

# Тип 2. Найти мощность алфавита

Это особенно важный тип для ЕГЭ-2027.

Даны:

- длина одного номера;
- количество номеров;
- ограничение на общий объём памяти.

Нужно найти максимально возможную мощность алфавита.

Здесь удобнее сначала определить, сколько байт может занимать **одна запись**.

Если на `K` записей выделено не более `V` байт:

```text
M <= V / K
```

Поскольку `M` — целое число байт, берём максимально допустимое целое значение.

Затем проверяем, какое максимальное число бит на символ помещается в этот объём.

---

# Пример по демоверсии ЕГЭ-2027

Серийный номер состоит из `157` символов.

Для хранения `12450` номеров отведено не более `955 Кбайт`.

Нужно определить максимально возможную мощность алфавита.

Переведём память в байты:

```text
955 * 1024 = 977920 байт
```

На один номер может приходиться не более:

```text
977920 // 12450 = 78 байт
```

Проверим, сколько бит на символ можно использовать.

Если `i = 4`:

```text
157 * 4 = 628 бит
```

В байтах:

```text
ceil(628 / 8) = 79 байт
```

Это уже слишком много.

Если `i = 3`:

```text
157 * 3 = 471 бит
ceil(471 / 8) = 59 байт
```

Подходит.

Значит, максимум:

```text
i = 3 бита на символ
```

Следовательно:

```text
N <= 2^3 = 8
```

Ответ:

```text
8
```

---

# Быстрый способ для задач на максимум алфавита

Если известен максимальный размер одной записи `M` байт, можно проверить условие:

```text
ceil(L * i / 8) <= M
```

или без функции округления:

```text
L * i <= 8 * M
```

После нахождения максимального `i`:

```text
Nmax = 2^i
```

Этот способ особенно удобен, когда требуется именно **максимальная мощность алфавита**.

---

# Тип 3. Найти длину пароля

Иногда известны:

- мощность алфавита;
- объём памяти на одну запись;
- требуется максимальная или минимальная длина идентификатора.

Сначала находим `i`, затем используем условие:

```text
ceil(L * i / 8) <= M
```

Для поиска максимальной длины удобно перейти к битам:

```text
L * i <= 8 * M
```

откуда:

```text
L <= (8 * M) / i
```

После этого берём подходящее целое значение в соответствии с условием задачи.

---

# Тип 4. Дополнительные сведения о пользователе или объекте

Иногда одна запись состоит не только из пароля или идентификатора, но и из дополнительной информации.

Например:

```text
вся запись = пароль + дополнительные сведения
```

Если на одного пользователя отведено `M` байт, а пароль занимает `P` байт, то на дополнительные сведения остаётся:

```text
M - P
```

байт.

Важно сначала отдельно посчитать минимальное целое число байт для пароля, а уже потом вычитать его из общего размера записи.

---

# Основной способ — рассуждение

Для большинства вариантов №11 программирование не требуется.

Обычно достаточно выписать четыре величины:

```text
N — количество символов алфавита
i — бит на символ
L — длина записи
M — байт на одну запись
```

и последовательно пройти цепочку:

```text
N -> i -> L*i бит -> M байт -> общий объём
```

или в обратную сторону:

```text
общий объём -> M байт -> i -> N
```

---

# Альтернативный способ — Python

Python удобен для проверки ответа или задач, где нужно перебрать возможные значения.

## Найти число бит на символ

```python
N = 26

i = 0
while 2 ** i < N:
    i += 1

print(i)
```

Получим:

```text
5
```

## Найти память на одну запись

```python
N = 26
L = 15

i = 0
while 2 ** i < N:
    i += 1

bits = L * i
bytes_per_item = (bits + 7) // 8

print(bytes_per_item)
```

## Найти максимальную мощность алфавита перебором

```python
L = 157
K = 12450
V = 955 * 1024

answer = 0

for N in range(1, 1000):
    i = 0
    while 2 ** i < N:
        i += 1

    bytes_per_item = (L * i + 7) // 8

    if bytes_per_item * K <= V:
        answer = N

print(answer)
```

Результат:

```text
8
```

Такой перебор хорош как проверка, но вручную задача решается быстрее.

---

# Как понять, какой способ выбрать

## Рассуждение лучше, если

- в задаче обычное посимвольное кодирование;
- нужно найти один из параметров по формулам;
- достаточно сравнить несколько степеней двойки;
- округление легко сделать вручную.

## Python удобнее, если

- хочется проверить вычисления;
- много ограничений;
- неизвестный параметр удобно перебрать;
- легко ошибиться на границе между двумя степенями двойки.

---

# Частые ошибки

## 1. Использовать формулу `N = 2^i` всегда

На самом деле:

```text
2^(i-1) < N <= 2^i
```

Например, при `i = 5` алфавит может содержать не только 32 символа, но любое количество от 17 до 32.

## 2. Не округлять байты вверх

Например:

```text
75 бит = 9.375 байта
```

но для хранения требуется:

```text
10 байт
```

## 3. Округлять после умножения на количество записей

Неверно:

```text
сначала сложить биты всех пользователей,
потом перевести в байты
```

Если в условии сказано, что для каждой записи выделено одинаковое минимальное целое число байт, округление выполняется **для каждой записи отдельно**.

## 4. Считать 1 Кбайт как 1000 байт

В задачах ЕГЭ обычно используется:

```text
1 Кбайт = 1024 байта
1 Мбайт = 1024 Кбайт
```

## 5. Перепутать длину идентификатора и размер алфавита

`L` — количество позиций в записи.

`N` — количество различных символов, которые могут стоять в одной позиции.

## 6. Забыть дополнительную информацию

Если в записи кроме пароля есть дополнительные сведения, их объём нужно учитывать отдельно.

---

# Быстрая памятка

```text
1. Находим минимальное i:
   2^i >= N

2. Информация в одном пароле:
   L * i бит

3. Память на одну запись:
   ceil(L * i / 8) байт

4. Для K записей:
   M * K

5. Если ищем максимальный алфавит:
   находим максимальное i, которое помещается,
   затем Nmax = 2^i

1 байт = 8 бит
1 Кбайт = 1024 байта
1 Мбайт = 1024 Кбайт
```

Главное в №11 — не сама формула, а правильный порядок вычислений и округлений.
