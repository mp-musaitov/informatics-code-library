# ЕГЭ №13. Количество программ исполнителя

> В проекте демоверсии ЕГЭ-2027 задание №13 изменено. Теперь это задача на анализ работы числового исполнителя и подсчёт количества программ, переводящих одно число в другое.

## Что проверяет задание

Дан исполнитель, который преобразует число на экране с помощью нескольких команд.

Нужно определить, **сколько различных программ** переводят исходное число в заданное конечное.

В демоверсии ЕГЭ-2027 исполнитель имеет две команды:

```text
A. Прибавь 1
B. Поменяй местами
```

Команда `B` разрешена не всегда: её можно применять только при выполнении условия на цифры числа.

Главная идея задания — построить все допустимые пути от начального числа к конечному, но **не перебирать сами строки команд вручную**.

---

# Основной принцип

Пусть нужно попасть из числа `x` в число `y`.

Обозначим:

```text
f(x) = количество программ, переводящих x в y
```

Если из `x` можно сделать несколько разных ходов, количество программ складывается:

```text
f(x) = f(результат команды A) + f(результат команды B) + ...
```

Но в сумму входят только **разрешённые команды**.

Это обычный подсчёт количества путей в графе состояний.

Каждое число — вершина графа, а допустимая команда — переход в другую вершину.

---

# Базовые условия рекурсии

Если дошли до цели:

```python
if x == y:
    return 1
```

Мы нашли одну программу.

Если число уже стало больше цели и все команды в задаче не позволяют вернуться к ней:

```python
if x > y:
    return 0
```

Такой путь не подходит.

> Условие `x > y → 0` можно использовать только тогда, когда по правилам конкретной задачи из такого состояния уже невозможно попасть в цель.

---

# Демоверсия ЕГЭ-2027

Исходное число:

```text
100
```

Конечное число:

```text
141
```

Команды:

```text
A. Прибавь 1
B. Поменяй местами две младшие цифры
```

Команда `B` разрешена только тогда, когда цифра десятков меньше цифры единиц.

Например:

```text
13 → 31
```

потому что:

```text
1 < 3
```

А для числа `31` команда применятьcя не может:

```text
3 < 1 — ложь
```

---

# Как выделить цифры числа

Для числа `x` цифра единиц:

```python
x % 10
```

Цифра десятков:

```python
(x // 10) % 10
```

или:

```python
(x % 100) // 10
```

Поэтому условие применения команды `B`:

```python
(x // 10) % 10 < x % 10
```

---

# Как поменять местами две младшие цифры

Например:

```text
123 → 132
```

Сотни и более старшие разряды оставляем без изменения:

```python
x // 100 * 100
```

Единицы переносим в десятки:

```python
(x % 10) * 10
```

Десятки переносим в единицы:

```python
(x // 10) % 10
```

Получаем:

```python
def change(x):
    return x // 100 * 100 + (x % 10) * 10 + (x // 10) % 10
```

Например:

```python
print(change(123))
```

получим:

```text
132
```

---

# Основной способ — рекурсия

Для демоверсии получается очень компактная программа:

```python
def change(x):
    return x // 100 * 100 + (x % 10) * 10 + (x // 10) % 10


def f(x, y):
    if x > y:
        return 0

    if x == y:
        return 1

    if (x // 10) % 10 < x % 10:
        return f(x + 1, y) + f(change(x), y)

    return f(x + 1, y)


print(f(100, 141))
```

Ответ демоверсии:

```text
16
```

---

# Почему здесь складываются результаты

Допустим, из некоторого числа доступны две команды:

```text
A → состояние 1
B → состояние 2
```

Все программы делятся на две группы:

```text
программы, начинающиеся с A
+
программы, начинающиеся с B
```

Поэтому:

```python
return f(a) + f(b)
```

Если команда `B` сейчас запрещена, остаются только программы, начинающиеся с `A`:

```python
return f(a)
```

Это ключевая идея всего задания.

---

# Важный момент: команда может уменьшить число

В старых классических задачах на количество программ часто встречались команды вроде:

```text
+1
*2
*3
```

Все они увеличивали число, поэтому условие

```python
if x > y:
    return 0
```

было очевидным.

В новом №13 команда может **переставлять цифры**, поэтому нельзя автоматически считать любое значение больше цели тупиком.

Нужно сначала проверить свойства команды.

Например:

```text
129 → 192
```

число увеличилось.

А если условие разрешало бы обратную перестановку:

```text
192 → 129
```

оно уменьшилось бы.

Поэтому базовые условия рекурсии всегда должны соответствовать конкретному исполнителю.

---

# Быстрый анализ команды перестановки

В демоверсии команда разрешена только если:

```text
десятки < единицы
```

После перестановки большая цифра переходит в разряд десятков.

Значит, число **увеличивается**.

Например:

```text
124 → 142
137 → 173
205 → 250
```

Следовательно, в демоверсионной задаче обе команды увеличивают число, и условие

```python
if x > y:
    return 0
```

безопасно.

Это полезнее понять, чем просто механически скопировать шаблон.

---

# Альтернативный способ — динамическое программирование

Если все переходы ведут только к большим числам, количество способов можно считать снизу вверх.

Идея:

```text
dp[n] = количество способов попасть в n
```

Начальная точка:

```python
dp[start] = 1
```

Затем каждый найденный способ передаём во все состояния, куда можно сделать следующий ход.

Для демоверсии:

```python
def change(x):
    return x // 100 * 100 + (x % 10) * 10 + (x // 10) % 10

start = 100
finish = 141

dp = [0] * (finish + 1)
dp[start] = 1

for x in range(start, finish):
    dp[x + 1] += dp[x]

    if (x // 10) % 10 < x % 10:
        y = change(x)
        if y <= finish:
            dp[y] += dp[x]

print(dp[finish])
```

Этот способ даёт тот же результат.

---

# Что выбрать: рекурсию или динамику

## Рекурсия удобнее, если

- команд немного;
- правила переходов легко записать функциями;
- нужно быстро перенести условие задачи в код;
- диапазон значений небольшой.

## Динамика удобнее, если

- все переходы направлены в одну сторону;
- состояний много;
- хочется избежать повторных вычислений рекурсии;
- нужно видеть количество способов попасть в каждое число.

Для №13 **рекурсивная функция обычно получается ближе всего к тексту условия**, поэтому её удобно использовать как основной шаблон.

---

# Мемоизация рекурсии

Обычная рекурсия может многократно вычислять одно и то же состояние.

Например, в число `120` можно прийти разными программами, а затем функция несколько раз заново посчитает все пути из `120`.

Можно сохранить уже найденные результаты:

```python
from functools import lru_cache


def change(x):
    return x // 100 * 100 + (x % 10) * 10 + (x // 10) % 10


@lru_cache(None)
def f(x):
    if x > 141:
        return 0

    if x == 141:
        return 1

    result = f(x + 1)

    if (x // 10) % 10 < x % 10:
        result += f(change(x))

    return result


print(f(100))
```

Для небольшого диапазона демоверсии это не обязательно, но для более крупных задач может заметно ускорить программу.

# Другие типы условий

В конкретном варианте могут измениться:

- сами команды;
- условие применения команды;
- начальное и конечное число;
- требование пройти через определённое число;
- требование не проходить через определённое число.

Поэтому важнее понимать структуру функции, чем запоминать конкретные `+1` и перестановку цифр.

---

# Обязательная вершина траектории

Если программа должна пройти через число `k`, а переходы не создают циклов, задачу часто можно разбить:

```text
start → k → finish
```

Количество программ:

```text
f(start, k) · f(k, finish)
```

То есть результаты **умножаются**, потому что каждую программу первой части можно соединить с каждой программой второй части.

---

# Запрещённая вершина

Если через число `k` проходить нельзя, в рекурсии добавляем:

```python
if x == k:
    return 0
```

Например:

```python
def f(x, y):
    if x == 120:
        return 0

    if x > y:
        return 0

    if x == y:
        return 1

    ...
```

# Частые ошибки

## 1. Считать количество чисел вместо количества программ

Один и тот же промежуточный результат может быть получен разными последовательностями команд.

Считаются именно **программы**, то есть пути.

## 2. Всегда применять обе команды

Если у команды есть условие, сначала проверяем его:

```python
if условие:
    ...
```

## 3. Неправильно выделять цифры

```python
x % 10          # единицы
(x // 10) % 10  # десятки
```

## 4. Неправильно переставлять цифры

Лучше вынести сложную команду в отдельную функцию:

```python
def change(x):
    ...
```

Так основной алгоритм остаётся читаемым.

## 5. Механически писать `x > y → 0`

Сначала убедитесь, что команды не позволяют уменьшить число и вернуться к цели.

## 6. Использовать `elif` там, где доступны сразу несколько независимых команд

Если из состояния разрешены обе команды, нужно посчитать **обе ветви** и сложить их результаты.

---

# Быстрая памятка

```text
1. Выписать команды исполнителя.
2. Для каждой команды определить условие применения.
3. Понять, увеличивает она число, уменьшает или может делать и то и другое.
4. Каждое число считать состоянием.
5. Дошли до цели → 1 программа.
6. Попали в невозможное состояние → 0 программ.
7. Если доступны несколько команд → результаты ветвей складываются.
8. Сложную команду вынести в отдельную функцию.
9. При большом числе повторов использовать мемоизацию или динамику.
```

Главная формула задания №13:

```text
количество программ из состояния
=
сумма количества программ из всех допустимых следующих состояний
```

Если ученик понимает эту идею, конкретные команды исполнителя уже становятся только технической частью задачи.
