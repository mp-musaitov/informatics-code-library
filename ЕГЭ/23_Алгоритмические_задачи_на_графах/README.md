# ЕГЭ №23. Алгоритмические задачи на графах

## Что проверяет задание

В проекте демоверсии ЕГЭ-2027 задание №23 стало алгоритмической задачей на графах.

В демоверсии дан текстовый файл с описанием **ациклического ориентированного взвешенного графа**. В каждой строке записаны:

```text
L M W
```

где:

- `L` — начальная вершина ребра;
- `M` — конечная вершина ребра;
- `W` — положительный вещественный вес ребра.

Нужно найти **целую часть длины кратчайшего пути из вершины 1 в вершину 100**.

Для проекта демоверсии ЕГЭ-2027 ответ:

```text
10971
```

---

# Главная идея

Граф удобно хранить как словарь списков смежности:

```python
a = {
    1: [[7, 5.5], [100, 12.0], [4, 2.5]],
    7: [[100, 2.0]],
    4: [[100, 8.0]]
}
```

Запись

```python
1: [[7, 5.5], [4, 2.5]]
```

означает:

```text
из вершины 1 можно перейти в 7 с весом 5.5
из вершины 1 можно перейти в 4 с весом 2.5
```

Так как граф **ориентированный**, если в файле есть ребро

```text
1 7 5.5
```

мы добавляем только переход `1 → 7`.

Обратное ребро `7 → 1` автоматически не существует.

---

# Основной способ: алгоритм Дейкстры

Все веса в условии положительные, поэтому для поиска кратчайшего пути удобно использовать алгоритм Дейкстры.

Будем хранить:

```python
dist[v]
```

— минимальную найденную длину пути от стартовой вершины до вершины `v`.

Для быстрого выбора вершины с наименьшим расстоянием используется очередь с приоритетом `heapq`.

---

# Шаг 1. Читаем граф из файла

```python
from heapq import heappush, heappop


a = {}

with open('23.txt') as f:
    for s in f:
        l, m, w = s.split()

        l = int(l)
        m = int(m)
        w = float(w)

        if l not in a:
            a[l] = []

        a[l].append([m, w])
```

Почему используется просто

```python
s.split()
```

а не, например,

```python
s.split(' ')
```

Потому что по условию между числами может быть произвольное количество пробелов и/или табуляций. Обычный `split()` корректно обработает оба случая.

---

# Шаг 2. Начальное расстояние

Стартуем из вершины `1`, поэтому:

```python
dist = {1: 0}
```

До стартовой вершины расстояние равно нулю.

Все остальные вершины пока считаем недостижимыми.

---

# Шаг 3. Очередь с приоритетом

```python
q = [(0, 1)]
```

Каждый элемент очереди имеет вид:

```text
(расстояние, вершина)
```

То есть сначала рассматривается вершина с наименьшим известным расстоянием.

---

# Шаг 4. Основной цикл Дейкстры

```python
while q:
    d, v = heappop(q)

    if d != dist[v]:
        continue

    for to, w in a.get(v, []):
        new_d = d + w

        if new_d < dist.get(to, float('inf')):
            dist[to] = new_d
            heappush(q, (new_d, to))
```

Разберём по смыслу.

### Получаем ближайшую вершину

```python
d, v = heappop(q)
```

`d` — расстояние до вершины,
`v` — номер вершины.

### Пропускаем устаревшую запись

```python
if d != dist[v]:
    continue
```

Одна и та же вершина может несколько раз попасть в очередь с разными расстояниями.

Если позже был найден более короткий путь, старая запись нам уже не нужна.

### Перебираем рёбра из вершины

```python
for to, w in a.get(v, []):
```

`to` — куда ведёт ребро,
`w` — его вес.

Используем

```python
a.get(v, [])
```

потому что из некоторых вершин может не выходить ни одного ребра.

### Пробуем улучшить расстояние

```python
new_d = d + w
```

Если новое расстояние меньше уже известного:

```python
if new_d < dist.get(to, float('inf')):
```

запоминаем его:

```python
dist[to] = new_d
```

и добавляем вершину в очередь:

```python
heappush(q, (new_d, to))
```

---

# Полное решение демоверсии

```python
from heapq import heappush, heappop


a = {}

with open('23.txt') as f:
    for s in f:
        l, m, w = s.split()

        l = int(l)
        m = int(m)
        w = float(w)

        if l not in a:
            a[l] = []

        a[l].append([m, w])


dist = {1: 0}

q = [(0, 1)]

while q:
    d, v = heappop(q)

    if d != dist[v]:
        continue

    for to, w in a.get(v, []):
        new_d = d + w

        if new_d < dist.get(to, float('inf')):
            dist[to] = new_d
            heappush(q, (new_d, to))


print(int(dist[100]))
```

---

# Почему в конце `int()`

По условию требуется вывести **целую часть** длины кратчайшего пути.

Например:

```python
x = 25.73
print(int(x))
```

получим:

```text
25
```

Так как веса положительные, для этой задачи `int()` даёт нужную целую часть.

Важно: округлять через `round()` здесь нельзя.

---

# Разбор типового примера

Пусть есть рёбра:

```text
1 7 5.5
7 100 2.0
1 100 12.0
1 4 2.5
4 100 8.0
```

Возможные пути из `1` в `100`:

```text
1 → 100       = 12
1 → 7 → 100   = 5.5 + 2 = 7.5
1 → 4 → 100   = 2.5 + 8 = 10.5
```

Кратчайший путь имеет длину:

```text
7.5
```

Целая часть:

```text
7
```

---

# Почему не нужно перебирать все пути

Можно было бы построить все возможные маршруты из `1` в `100`, посчитать длину каждого и выбрать минимальную.

Для маленького графа это сработает.

Но количество путей может расти очень быстро. Поэтому универсальнее хранить лучшее найденное расстояние до каждой вершины и не перебирать все маршруты целиком.

Именно это делает Дейкстра.

---

# Альтернативный способ: топологическая сортировка + динамика

В условии демоверсии специально сказано, что граф **ациклический**. Такой ориентированный ациклический граф называют DAG.

Для DAG вершины можно расположить в **топологическом порядке**: каждое ребро `v → to` будет вести из уже обработанной вершины в ещё не обработанную.

Например:

```text
1 → 3
1 → 4
3 → 7
4 → 7
```

Один из возможных топологических порядков:

```text
1, 3, 4, 7
```

## Как получить топологический порядок

Удобный способ — алгоритм Кана.

Сначала считаем для каждой вершины количество входящих рёбер:

```python
indegree = {}

for v in a:
    indegree.setdefault(v, 0)

    for to, w in a[v]:
        indegree[to] = indegree.get(to, 0) + 1
```

Вершины с нулевой входной степенью можно обрабатывать сразу:

```python
from collections import deque

q = deque(
    v for v in indegree
    if indegree[v] == 0
)

order = []

while q:
    v = q.popleft()
    order.append(v)

    for to, w in a.get(v, []):
        indegree[to] -= 1

        if indegree[to] == 0:
            q.append(to)
```

После этого `order` содержит топологический порядок вершин.

Если граф действительно ациклический, в `order` попадут все вершины.

## Кратчайший путь по топологическому порядку

Теперь очередь с приоритетом уже не нужна.

```python
dist = {1: 0}

for v in order:
    if v not in dist:
        continue

    for to, w in a.get(v, []):
        new_d = dist[v] + w
        dist[to] = min(
            dist.get(to, float('inf')),
            new_d
        )

print(int(dist[100]))
```

Когда обрабатывается вершина `v`, все пути в неё через предыдущие вершины уже рассмотрены. Поэтому её значение можно безопасно использовать для обновления следующих вершин.

## Полный вариант для DAG

```python
from collections import deque


a = {}
indegree = {}

with open('23.txt') as f:
    for s in f:
        l, m, w = s.split()

        l = int(l)
        m = int(m)
        w = float(w)

        a.setdefault(l, []).append([m, w])

        indegree.setdefault(l, 0)
        indegree[m] = indegree.get(m, 0) + 1


q = deque(
    v for v in indegree
    if indegree[v] == 0
)

order = []

while q:
    v = q.popleft()
    order.append(v)

    for to, w in a.get(v, []):
        indegree[to] -= 1

        if indegree[to] == 0:
            q.append(to)


dist = {1: 0}

for v in order:
    if v not in dist:
        continue

    for to, w in a.get(v, []):
        new_d = dist[v] + w
        dist[to] = min(
            dist.get(to, float('inf')),
            new_d
        )

print(int(dist[100]))
```

Для демоверсии оба способа — Дейкстра и топологическая сортировка с динамикой — дают один и тот же ответ.

Для первого знакомства с №23 Дейкстра остаётся удобным основным шаблоном для кратчайшего пути с положительными весами. Но топологический порядок особенно важен для других вариантов DAG: максимального пути и количества путей.

# Какие ещё типы №23 могут встречаться

После изменения задания в банке уже встречаются и другие задачи на ациклические ориентированные графы. Например:

- найти **максимальную** длину пути;
- найти путь до одной из вершин-тупиков;
- посчитать количество различных путей;
- посчитать пути, проходящие через определённую вершину или ребро.

Для них алгоритм Дейкстры подходит не всегда.

Поэтому важно сначала определить, **что именно требуется посчитать**.

```text
кратчайший путь + положительные веса → Дейкстра

максимальный путь в DAG              → динамическое программирование

количество путей в DAG               → динамическое программирование
```

---

# Частые ошибки

1. Добавлять обратное ребро, забывая, что граф ориентированный.
2. Читать `W` как `int`, хотя вес вещественный.
3. Использовать `split(' ')` при произвольном количестве пробелов и табуляций.
4. Заранее создавать список на `1000` вершин и ошибаться из-за непоследовательной нумерации.
5. Обращаться к `a[v]`, когда из вершины может не выходить ни одного ребра.
6. Использовать `round()` вместо взятия целой части.
7. Искать минимальное отдельное ребро вместо минимальной **суммы весов пути**.
8. Считать граф неориентированным.
9. Путать вершину назначения `100` с максимальным номером вершины: в условии номера могут идти не подряд и быть больше `100`.

# Быстрая памятка

```text
Файл:
L M W

L → M
W — вес ребра

Граф ориентированный.

Хранение:
a[L].append([M, W])

Старт:
dist = {1: 0}
q = [(0, 1)]

Обновление:
new_d = d + w

если new_d меньше старого расстояния:
    сохранить
    добавить в heap

Ответ демоверсии:
int(dist[100])
```

Главная мысль №23:

> **Сначала нужно превратить строки файла в граф, а затем выбрать алгоритм под вопрос задачи. Для кратчайшего пути с положительными весами надёжный основной шаблон — алгоритм Дейкстры.**
