# №3. Базы данных

## Что проверяет задание

Задание №3 проверяет умение искать информацию в **реляционной многотабличной базе данных**.

Обычно к заданию прилагается файл электронной таблицы с несколькими листами. На одном листе находятся события или операции, а на других — справочники: товары, организации, районы, категории и т. п.

Задача ученика — понять, **как связаны таблицы**, отобрать нужные записи и выполнить требуемый расчёт.

Главная идея №3: данные, необходимые для ответа, часто находятся **не в одной таблице**.

---

# Что нужно знать

## Таблица

Таблица состоит из строк и столбцов.

Строка — отдельная запись.

Столбец — поле (характеристика записи).

Например:

| ID товара | Название | Цена |
|---:|---|---:|
| 101 | Сок | 120 |
| 102 | Вода | 60 |

## Ключ

Таблицы связываются через общее поле — идентификатор.

Например, таблица движения товара может содержать:

| ID товара | ID магазина | Количество |
|---:|---:|---:|
| 101 | 5 | 20 |

а справочник товаров:

| ID товара | Название |
|---:|---|
| 101 | Сок |

По значению `101` можно определить, что первая запись относится к соку.

## Почему нельзя смотреть только на название

В основной таблице вместо понятного человеку значения часто записан только код:

```text
ID магазина = 17
```

Чтобы узнать район или название магазина, нужно найти `17` в другой таблице.

Это и есть связь между таблицами.

# Основной принцип решения

Практически любое №3 удобно раскладывать на четыре действия:

```text
1. Найти таблицу с основными записями.
2. Определить ключевые поля.
3. Через справочники выяснить, какие ID удовлетворяют условию.
4. Отфильтровать основную таблицу и выполнить расчёт.
```

Очень полезно сначала перевести условие задачи в обычный план.

Например:

> Найти количество товаров категории «Напитки», проданных в магазинах Центрального района.

Значит, нам нужны:

```text
товары → категория «Напитки» → нужные ID товаров

магазины → Центральный район → нужные ID магазинов

движение товаров → оставить строки с этими ID

посчитать продажи
```

Не нужно начинать с формул, пока эта цепочка не понятна.

# Основной способ — электронная таблица

Для типичного задания №3 это наиболее естественный способ: файл уже представлен в виде таблиц, а нужные данные удобно искать фильтрами.

## Шаг 1. Изучить листы

Сначала посмотрите названия листов.

Например:

```text
Движение товаров
Товары
Магазины
```

Определите роль каждого листа.

## Шаг 2. Найти ключи

Например:

```text
Движение товаров.ID товара ↔ Товары.ID товара
Движение товаров.ID магазина ↔ Магазины.ID магазина
```

## Шаг 3. Отобрать нужные записи в справочнике

Если нужны магазины определённого района, включите фильтр на листе `Магазины` и оставьте нужный район.

Получите, например:

```text
ID магазинов: 3, 8, 15
```

Аналогично можно получить ID нужных товаров.

## Шаг 4. Перейти к основной таблице

Теперь в таблице движения оставляем только строки с нужными идентификаторами.

## Шаг 5. Выполнить требуемое действие

Условие может требовать:

- сумму;
- количество записей;
- количество единиц товара;
- разность поступления и продажи;
- стоимость;
- максимум или минимум.

Важно считать именно ту величину, которая указана в условии.

---

# Полезные инструменты электронной таблицы

## Фильтр

Для №3 фильтр часто является главным инструментом.

Он позволяет оставить только строки, удовлетворяющие условию.

Например:

```text
Район = Центральный
```

или несколько ID одновременно.

## Сортировка

Иногда удобно отсортировать данные по ID, дате или другому полю, но сортировка сама по себе записи не отбирает.

Не путайте сортировку и фильтр.

## СУММ

Если после фильтра нужно сложить значения, обычная сумма может быть полезна, но нужно учитывать особенности конкретного редактора и работу с отфильтрованными строками.

Надёжный вариант — внимательно проверить, какие строки участвуют в расчёте.

## Вспомогательный столбец

Если требуется вычислить величину для каждой записи, можно добавить вспомогательный столбец.

Например:

```text
Стоимость = Цена × Количество
```

а затем суммировать только подходящие записи.

# Альтернативный способ — Python

№3 можно решать программно, особенно если структура файла хорошо понятна.

Однако для чтения `.xlsx` обычно нужна дополнительная библиотека, например `openpyxl` или `pandas`, поэтому на экзамене этот способ зависит от доступного программного обеспечения.

Общий алгоритм остаётся тем же:

```text
1. прочитать справочники;
2. определить нужные ID;
3. прочитать основную таблицу;
4. проверить условия;
5. накопить ответ.
```

Упрощённая логика программы может выглядеть так:

```python
needed_products = {101, 105, 120}
needed_shops = {3, 8, 15}

answer = 0

for product_id, shop_id, amount in records:
    if product_id in needed_products and shop_id in needed_shops:
        answer += amount

print(answer)
```

Здесь множества позволяют быстро проверить принадлежность ID нужной группе.

> Этот код показывает алгоритм. Способ чтения конкретного файла зависит от его структуры и доступных на экзаменационном компьютере библиотек.

# Альтернативный приём — подтянуть данные в одну таблицу

Если ученику сложно постоянно переключаться между листами, можно создать вспомогательные столбцы в основной таблице и подтянуть туда значения из справочников.

Идея:

```text
ID магазина → район
ID товара → категория
```

После этого основная таблица становится примерно такой:

| ID товара | Категория | ID магазина | Район | Количество |
|---:|---|---:|---|---:|
| 101 | Напитки | 3 | Центральный | 20 |

И дальше задача решается обычным фильтром.

Для такого объединения можно использовать функции поиска электронной таблицы, если ученик уверенно ими владеет.

Это не всегда самый быстрый способ, но он хорошо показывает сам принцип реляционной базы данных.

---

# Как понять, какой способ выбрать

## Фильтры в электронной таблице удобнее, если

- задача типовая;
- справочники небольшие;
- нужных ID немного;
- условие состоит из нескольких простых отборов;
- ответ можно получить одной суммой или подсчётом.

## Вспомогательные столбцы удобнее, если

- приходится много раз обращаться к справочникам;
- условие использует несколько характеристик одной записи;
- хочется видеть все необходимые данные на одном листе.

## Python может быть удобнее, если

- данных много;
- условие сложное;
- нужно проверить большое число записей автоматически;
- ученик хорошо умеет читать электронные таблицы программно и нужные библиотеки доступны.

Для большинства обычных вариантов №3 **электронная таблица остаётся наиболее практичным способом**.

# Типовые расчёты

## Количество записей

Нужно посчитать, сколько строк удовлетворяет условию.

Не путать с суммой значений в столбце.

## Общее количество товара

```text
ответ = сумма поля «Количество» по подходящим строкам
```

## Стоимость

Если даны цена и количество:

```text
стоимость = цена × количество
```

## Остаток

Если отдельно указаны поступление и продажа:

```text
остаток = поступило - продано
```

Всегда сначала определяйте смысл столбцов по условию и заголовкам файла.

# Частые ошибки

## 1. Фильтровать ID без справочника

Код `15` сам по себе ничего не говорит о районе, товаре или организации.

Сначала нужно определить его значение через связанную таблицу.

## 2. Перепутать ключи

Например, сравнивать `ID товара` с `ID магазина`.

Перед решением полезно явно записать связи таблиц.

## 3. Посчитать строки вместо количества товара

Три подходящие строки вовсе не означают три проданных товара.

Если количества равны:

```text
10
25
7
```

то результат по количеству товара — `42`, а не `3`.

## 4. Использовать ИЛИ вместо И

Если требуется одновременно:

```text
категория = Напитки
И
район = Центральный
```

строка должна удовлетворять обоим условиям.

## 5. Забыть один из подходящих ID

После фильтрации справочника внимательно выпишите все подходящие идентификаторы.

## 6. Потерять строки после сортировки

Сортировать нужно всю таблицу целиком. Иначе данные разных столбцов могут перестать соответствовать друг другу.

## 7. Не проверить единицы измерения

В условии могут спрашивать рубли, штуки, килограммы, литры и т. д.

Ответ должен соответствовать требуемой величине.

# Быстрая памятка

```text
1. Прочитай вопрос — что именно нужно найти?
2. Посмотри все листы файла.
3. Найди основную таблицу и справочники.
4. Определи поля, связывающие таблицы.
5. Найди в справочниках нужные ID.
6. Отфильтруй основную таблицу.
7. Выполни нужный расчёт.
8. Проверь: считаешь строки или значения?
9. Проверь единицы измерения.
```

## Главная схема №3

```text
УСЛОВИЕ
   ↓
СПРАВОЧНИКИ
   ↓
НУЖНЫЕ ID
   ↓
ОСНОВНАЯ ТАБЛИЦА
   ↓
ФИЛЬТР
   ↓
РАСЧЁТ
   ↓
ОТВЕТ
```

Главное в задании №3 — не знание конкретной функции Excel, а понимание **связей между таблицами через ключевые поля**.
