# №7. Кодирование информации

## Что проверяет задание

В задании №7 нужно уметь вычислять объём графической и звуковой информации, работать с единицами измерения и понимать, как параметры кодирования влияют на размер файла.

Чаще всего встречаются задачи на:

- растровые изображения;
- количество цветов и глубину цвета;
- звук: частоту дискретизации, глубину кодирования и число каналов;
- изменение параметров изображения или звука;
- повторное кодирование изображения и экономию памяти или трафика;
- сжатие данных;
- перевод между битами, байтами, Кбайтами, Мбайтами и Гбайтами.

Основной принцип задания: **сначала определить, из чего складывается объём информации, затем привести все единицы к совместимому виду и только после этого считать**.

# 1. Единицы измерения

Нужно уверенно помнить:

```text
1 байт = 8 бит
1 Кбайт = 1024 байта = 2^10 байт
1 Мбайт = 1024 Кбайт = 2^20 байт
1 Гбайт = 1024 Мбайт = 2^30 байт
```

Если объём получен в битах:

```text
в байты  → делим на 8
в Кбайты → делим на 8 · 1024
в Мбайты → делим на 8 · 1024 · 1024
в Гбайты → делим на 8 · 1024 · 1024 · 1024
```

В Python удобно использовать степени двойки:

```python
bits / 2**3   # байты
bits / 2**13  # Кбайты
bits / 2**23  # Мбайты
bits / 2**33  # Гбайты
```

# 2. Растровые изображения

## Основная формула

Объём несжатого растрового изображения:

```text
I = K · i
```

где:

```text
I — объём изображения в битах;
K — количество пикселей;
i — глубина цвета, бит на пиксель.
```

Если изображение имеет размер `W × H`, то:

```text
K = W · H
```

Следовательно:

```text
I = W · H · i
```

---

## Количество цветов и глубина цвета

Если для одного пикселя используется `i` бит, можно закодировать:

```text
N = 2^i
```

цветов.

Примеры:

```text
1 бит  → 2 цвета
2 бита → 4 цвета
4 бита → 16 цветов
8 бит  → 256 цветов
16 бит → 65536 цветов
24 бита → 16777216 цветов
```

Если дано количество цветов, ищем минимальное `i`, для которого:

```text
2^i ≥ N
```

Например, для 100 цветов:

```text
2^6 = 64   — мало
2^7 = 128  — достаточно
```

Значит, требуется `7 бит` на пиксель.

---

# Основной способ для изображения — формулы

Например, изображение имеет размер:

```text
800 × 600 пикселей
```

и глубину цвета:

```text
16 бит
```

Объём:

```text
I = 800 · 600 · 16
```

Получаем биты, а затем переводим их в нужную единицу.

В Python:

```python
w = 800
h = 600
depth = 16

bits = w * h * depth
kbytes = bits / 8 / 1024

print(kbytes)
```

Для простых задач программирование здесь обычно не нужно: формула быстрее.

# 3. Если изменяются размеры изображения

Если ширину и высоту уменьшили в `k` раз, количество пикселей уменьшится в:

```text
k² раз
```

Например:

```text
ширина уменьшена в 2 раза
высота уменьшена в 2 раза
```

значит:

```text
число пикселей уменьшилось в 4 раза
```

Это очень частая ловушка: нельзя считать, что объём уменьшился только в 2 раза.

Если одновременно меняется глубина цвета, удобно сравнивать объёмы отношением:

```text
I₂ / I₁ = (W₂ / W₁) · (H₂ / H₁) · (i₂ / i₁)
```

Например:

```text
ширина /2
высота /2
глубина цвета 16 → 8 бит
```

тогда:

```text
I₂ / I₁ = 1/2 · 1/2 · 8/16 = 1/8
```

Новый файл в 8 раз меньше исходного.

# 4. Повторное кодирование и экономия памяти или трафика

Это отдельный и очень важный тип задачи.

В условии могут дать исходное изображение, а затем сообщить, что перед передачей или хранением его **оцифровывают повторно** с другими параметрами:

- уменьшают ширину и высоту;
- уменьшают глубину цвета;
- меняют сразу оба параметра.

Здесь не нужно искать коэффициент сжатия. Нужно **отдельно вычислить объём исходного и нового изображения**, а затем найти разность.

## Алгоритм

```text
1. Найти глубину цвета исходного изображения.
2. Найти объём исходного изображения.
3. Найти объём изображения после повторного кодирования.
4. Вычесть: экономия на одном файле = Iисх - Iнов.
5. Умножить на количество файлов.
6. Перевести результат в требуемые единицы.
7. Выполнить округление строго по условию.
```

Если исходная палитра содержит `N` цветов, глубина цвета равна минимальному `i`, для которого:

```text
2^i ≥ N
```

---

## Пример: экономия трафика после повторного кодирования

Исходная фотография:

```text
8000 × 6000 пикселей
158543 цвета
```

После повторного кодирования:

```text
320 × 240 пикселей
6 бит на пиксель
```

Количество фотографий:

```text
1 327 573
```

Нужно найти, сколько Гбайт трафика экономится. Сжатие данных не производится.

### Шаг 1. Определяем глубину цвета исходной фотографии

```text
2^17 = 131072   — недостаточно
2^18 = 262144   — достаточно
```

Значит:

```text
i = 18 бит
```

### Шаг 2. Исходный объём одной фотографии

```text
I₁ = 8000 · 6000 · 18
   = 864000000 бит
```

### Шаг 3. Новый объём одной фотографии

```text
I₂ = 320 · 240 · 6
   = 460800 бит
```

### Шаг 4. Экономия на одной фотографии

```text
ΔI = I₁ - I₂
```

### Шаг 5. Умножаем на количество фотографий

```text
ΔIобщ = (I₁ - I₂) · 1327573
```

### Шаг 6. Переводим биты в Гбайты

```text
ΔIобщ / 8 / 1024³
```

В Python:

```python
old = 8000 * 6000 * 18
new = 320 * 240 * 6
count = 1_327_573

saved = (old - new) * count
answer = saved / 8 / 1024**3

print(answer)
print(int(answer))
```

Получается примерно:

```text
133459.8435 Гбайт
```

По условию требуется **целая часть**, поэтому ответ:

```text
133459
```

---

## Важное различие

Фраза:

```text
«изображение оцифровывается повторно с меньшим разрешением и глубиной цвета»
```

не означает применение алгоритма сжатия.

Мы просто получаем другое растровое изображение с меньшим количеством информации.

А фраза:

```text
«файл был сжат на 30%»
```

означает уже применение коэффициента сжатия.

Это два разных типа вычислений.

# 5. Ограничение по объёму и максимальное количество цветов

Иногда известен максимальный объём файла, а нужно определить максимально возможное количество цветов.

Алгоритм:

```text
1. Перевести допустимый объём в биты.
2. Найти количество пикселей.
3. Вычислить, сколько бит можно выделить на один пиксель.
4. Взять целое число бит, которое не превышает лимит.
5. Найти количество цветов: 2^i.
```

Если получилось, например:

```text
i = 7.8 бита
```

нельзя взять `8`, если это приведёт к превышению памяти.

Берём:

```text
7 бит
```

и получаем:

```text
2^7 = 128 цветов
```

# 6. Звуковая информация

## Основная формула

Объём несжатого звука:

```text
I = f · i · t · c
```

где:

```text
f — частота дискретизации, измерений в секунду (Гц);
i — глубина кодирования одного измерения, бит;
t — длительность, секунд;
c — количество каналов.
```

Для моно:

```text
c = 1
```

Для стерео:

```text
c = 2
```

---

## Пример

Голосовое сообщение:

```text
частота: 12000 Гц
глубина: 16 бит
стерео
длительность: 3 мин 10 с
```

Сначала переводим время:

```text
3 · 60 + 10 = 190 секунд
```

Затем:

```text
I = 12000 · 16 · 190 · 2
```

Получаем объём в битах и переводим в Кбайты:

```python
f = 12000
depth = 16
time = 3 * 60 + 10
channels = 2

bits = f * depth * time * channels
kbytes = bits / 8 / 1024

print(kbytes)
```

---

# 7. Как параметры влияют на размер звука

Для звука объём прямо пропорционален каждому параметру:

```text
частота ×2       → объём ×2
глубина ×2       → объём ×2
длительность ×2  → объём ×2
моно → стерео    → объём ×2
```

Если меняются несколько параметров одновременно, коэффициенты перемножаются.

Например:

```text
частоту увеличили в 2 раза,
глубину уменьшили в 2 раза,
стерео заменили на моно.
```

Тогда:

```text
2 · 1/2 · 1/2 = 1/2
```

Новый файл будет в 2 раза меньше.

# 8. Сжатие данных

Если файл после сжатия стал на `p%` меньше, остаётся:

```text
100% - p%
```

Например, файл уменьшился на 25%:

```text
остаётся 75%
```

Значит:

```text
Iсжат = Iисх · 0.75
```

Обратная задача:

если известен сжатый размер, а сжатие уменьшило файл на 25%, то:

```text
Iисх = Iсжат / 0.75
```

Не путайте:

```text
уменьшился на 25%  ≠  стал равен 25%
```

# 9. Округление

В №7 внимательно смотрите на формулировку.

Если спрашивают:

```text
наименьшее целое количество Кбайт, необходимое для хранения
```

нужно округлять вверх.

Python:

```python
import math

answer = math.ceil(bits / 8 / 1024)
```

Если сказано:

```text
укажите целую часть полученного числа
```

дробная часть просто отбрасывается:

```python
answer = int(bits / 8 / 1024)
```

Это разные действия.

# Альтернативный способ — Python

Python полезен, когда:

- много вычислений;
- одновременно меняются несколько параметров;
- требуется найти разницу между исходным и повторно закодированным файлом;
- файлов очень много;
- требуется округление;
- хочется проверить ручной расчёт.

Универсальный шаблон для изображения:

```python
w = ...
h = ...
depth = ...

bits = w * h * depth
answer = bits / 8 / 1024

print(answer)
```

Шаблон для экономии после повторного кодирования:

```python
old = old_w * old_h * old_depth
new = new_w * new_h * new_depth

saved = (old - new) * count
answer = saved / 8 / 1024**3

print(answer)
```

Универсальный шаблон для звука:

```python
frequency = ...
depth = ...
time = ...
channels = ...

bits = frequency * depth * time * channels
answer = bits / 8 / 1024

print(answer)
```

Но основной способ для №7 — всё-таки **формулы и отношения величин**. В большинстве вариантов это быстрее и прозрачнее программы.

---

# Как понять, какой способ выбрать

**Формула удобнее**, если параметры даны напрямую и нужно сделать один расчёт.

**Два отдельных объёма и их разность** удобнее, если изображение повторно кодируется с новыми параметрами и спрашивается экономия памяти или трафика.

**Отношение объёмов удобнее**, если исходный файл уже известен и изменяются размеры, глубина цвета, частота, каналы или другие параметры.

**Python удобнее**, если вычисления громоздкие, требуется несколько преобразований или важно корректно округлить результат.

# Частые ошибки

## 1. Забыть перевести биты в байты

Формулы для изображения и звука обычно дают результат именно в **битах**.

## 2. Использовать 1000 вместо 1024

В задачах ЕГЭ:

```text
1 Кбайт = 1024 байта
1 Мбайт = 1024 Кбайта
1 Гбайт = 1024 Мбайта
```

## 3. Забыть про число каналов

```text
моно   → 1
стерео → 2
```

## 4. Не перевести минуты в секунды

```text
2 мин 20 с = 2 · 60 + 20 = 140 с
```

## 5. Считать уменьшение ширины и высоты как один коэффициент

Если обе стороны уменьшили вдвое, количество пикселей уменьшается в 4 раза.

## 6. Перепутать число цветов и глубину цвета

```text
N = 2^i
```

256 цветов — это 8 бит, а не 256 бит.

## 7. Принять повторное кодирование за процентное сжатие

Если изменились разрешение или глубина цвета, нужно пересчитать новый объём по его параметрам.

## 8. Неправильно применить процент сжатия

Уменьшение на 20% означает, что осталось 80% исходного объёма.

## 9. Неправильно округлить

`int()` и `ceil()` дают разные результаты и выбираются по формулировке задачи.

# Быстрая памятка

```text
ИЗОБРАЖЕНИЕ
I = W · H · i
N = 2^i

ПОВТОРНОЕ КОДИРОВАНИЕ
Iисх = W1 · H1 · i1
Iнов = W2 · H2 · i2
экономия = (Iисх - Iнов) · количество файлов

ЗВУК
I = f · i · t · c

ЕДИНИЦЫ
1 байт = 8 бит
1 Кбайт = 2^10 байт
1 Мбайт = 2^20 байт
1 Гбайт = 2^30 байт

СТЕРЕО
c = 2

СЖАТИЕ НА p%
остаётся (100 - p)%

ОКРУГЛЕНИЕ
«наименьшее целое необходимое» → вверх
«целая часть» → отбросить дробь
```

Главное в №7 — **не заучивать десяток отдельных формул**, а видеть одну общую идею: объём зависит от числа элементов и количества бит, выделяемых на один элемент.
