# ОГЭ №15. Исполнитель Робот

## Что проверяет задание

Нужно составить алгоритм для исполнителя Робот, который работает на клетчатом поле со стенами.

Главная особенность №15: программа обычно должна работать **не для одного конкретного рисунка**, а для целого класса допустимых обстановок. Поэтому здесь важно не запомнить маршрут, а научиться использовать стены и свободные клетки как ориентиры.

---

# Основные команды Робота

В среде Кумир с исполнителем Робот используются команды движения:

```kumir
вверх
вниз
влево
вправо
```

и команда:

```kumir
закрасить
```

Она закрашивает клетку, в которой Робот находится сейчас.

Перед движением можно проверять обстановку:

```kumir
сверху свободно
снизу свободно
слева свободно
справа свободно
```

или наличие стены:

```kumir
сверху стена
снизу стена
слева стена
справа стена
```

---

# Каркас программы в Кумир

Полная программа обычно имеет такой вид:

```kumir
использовать Робот

алг
нач
    ...
кон
```

Например, если справа гарантированно свободно:

```kumir
использовать Робот

алг
нач
    закрасить
    вправо
    закрасить
кон
```

В экзаменационной задаче вместо многоточия записывается алгоритм под конкретное условие.

---

# Главное правило безопасности

Если наличие стены заранее неизвестно, нельзя просто отдавать команду движения.

Опасно:

```kumir
вправо
```

если справа может находиться стена.

Безопасный вариант:

```kumir
если справа свободно то
    вправо
все
```

Но если по условию гарантировано, что справа свободно, дополнительная проверка не нужна.

---

# Цикл «пока»

Когда расстояние заранее неизвестно, вместо повторения одинаковых команд используется цикл.

Например, пройти вправо до стены:

```kumir
нц пока справа свободно
    вправо
кц
```

После завершения цикла Робот стоит в клетке непосредственно слева от стены.

Если по пути нужно закрашивать клетки:

```kumir
нц пока справа свободно
    закрасить
    вправо
кц
закрасить
```

Последняя команда `закрасить` нужна потому, что цикл прекращается уже в последней клетке перед стеной.

---

# Важный вопрос: когда закрашивать клетку

Сравним два фрагмента.

Вариант 1:

```kumir
нц пока справа свободно
    закрасить
    вправо
кц
```

Начальная клетка закрашивается, а последняя клетка перед стеной — нет.

Вариант 2:

```kumir
нц пока справа свободно
    вправо
    закрасить
кц
```

Начальная клетка не закрашивается, зато закрашивается каждая клетка, в которую Робот пришёл.

Поэтому положение команды `закрасить` внутри цикла определяется условием задачи.

---

# Движение вдоль стены

Стена часто используется не как препятствие, а как ориентир.

Например, пока сверху есть стена, Робот движется вправо:

```kumir
нц пока сверху стена
    вправо
кц
```

После завершения цикла стена сверху закончилась.

Такой алгоритм не зависит от длины стены.

Но перед командой `вправо` нужно быть уверенным из условия, что справа на всём этом участке свободно. Проверка стены сверху сама по себе не гарантирует отсутствие стены справа.

---

# Условие «если»

Если действие нужно выполнить только в определённой ситуации:

```kumir
если снизу свободно то
    вниз
все
```

Если возможны два разных действия:

```kumir
если справа свободно то
    вправо
иначе
    вниз
все
```

В №15 условие удобно использовать для локального выбора, а цикл — для повторяющегося движения неизвестной длины.

---

# Пример 1. Закрасить клетки до стены справа

Пусть Робот находится в горизонтальном коридоре. Справа на некотором неизвестном расстоянии находится стена. Нужно закрасить все клетки от начальной до последней клетки перед стеной.

```kumir
использовать Робот

алг
нач
    нц пока справа свободно
        закрасить
        вправо
    кц
    закрасить
кон
```

Почему решение универсально: в программе нигде не указано количество шагов. Оно определяется самой обстановкой.

---

# Пример 2. Дойти до конца стены

Пусть непосредственно сверху от Робота начинается горизонтальная стена. Справа на пути Робота препятствий нет. Нужно двигаться вправо до конца этой стены.

```kumir
использовать Робот

алг
нач
    нц пока сверху стена
        вправо
    кц
кон
```

Здесь ориентир — не количество клеток, а наличие стены сверху.

---

# Пример 3. Закрашивать клетки вдоль стены

Пусть Робот движется вправо вдоль стены, расположенной сверху, и должен закрасить клетки под стеной.

```kumir
использовать Робот

алг
нач
    нц пока сверху стена
        закрасить
        вправо
    кц
кон
```

Обратите внимание на границу: после выхода из цикла сверху стены уже нет, поэтому новая клетка не относится к участку под стеной и не закрашивается.

---

# Как строить решение

Удобно идти не от команд, а от ориентиров.

Сначала мысленно опишите маршрут словами:

```text
дойти до стены
→ двигаться вдоль стены
→ найти её конец
→ перейти на следующий участок
→ закрасить нужные клетки
```

После этого каждую фразу переводите в конструкцию Кумир:

```text
неизвестное расстояние → цикл «пока»
проверка обстановки    → «если»
положение стены        → условие цикла
повторяющееся действие → тело цикла
```

---

# Почему фиксированное число шагов часто неверно

Например:

```kumir
вправо
вправо
вправо
вправо
```

работает только для обстановки, где действительно нужны четыре шага.

Если длина участка в условии не фиксирована, программа должна определять её по стенам или свободным клеткам.

Поэтому обычно правильная идея выглядит так:

```kumir
нц пока справа свободно
    вправо
кц
```

---

# Как проверять программу

Не ограничивайтесь картинкой из условия. Мысленно измените допустимую обстановку:

- сделайте стену короче;
- сделайте стену длиннее;
- переместите начальную позицию в пределах разрешённого;
- проверьте минимально возможный участок.

Если после такого изменения программа всё ещё выполняет требование, решение действительно построено для класса обстановок.

Особенно полезно пройти алгоритм вручную по клеткам и каждый раз проверять:

```text
где Робот находится сейчас?
какое условие истинно?
какая команда выполнится?
может ли движение привести к столкновению?
какая клетка будет закрашена?
```

---

# Частые ошибки

1. Решать только рисунок из примера и использовать фиксированное количество шагов.
2. Двигаться в направлении, где стена не исключена условием.
3. Путать `справа свободно` и `справа стена`.
4. Забывать, что условие цикла проверяется **до** выполнения его тела.
5. Терять последнюю клетку при конструкции «закрасить → двигаться».
6. Наоборот, закрашивать лишнюю клетку уже после конца нужного участка.
7. Создавать цикл, внутри которого ничего не меняется и условие никогда не станет ложным.
8. Считать, что наличие стены сверху автоматически означает свободный путь справа.
9. Использовать конкретные размеры поля, если они не гарантированы условием.

---

# Быстрая памятка

```kumir
использовать Робот

алг
нач
    нц пока справа свободно
        вправо
    кц
кон
```

Главная схема №15:

```text
1. Найти ориентир.
2. Определить, какое условие сообщает о достижении ориентира.
3. Неизвестное расстояние заменить циклом.
4. Проверить границы: начальную и последнюю клетки.
5. Убедиться, что Робот не может врезаться в стену.
6. Проверить алгоритм на нескольких допустимых обстановках.
```

Главная мысль:

> **Хорошая программа для Робота зависит от свойств обстановки, заданных в условии, а не от размеров конкретного рисунка.**
