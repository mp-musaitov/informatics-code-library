# Жадные алгоритмы

Жадный алгоритм на каждом шаге выбирает вариант, который выглядит лучшим прямо сейчас, и не возвращается к уже сделанному выбору.

Примеры локального выбора:

- взять самый короткий объект;
- выбрать мероприятие, которое закончится раньше остальных;
- использовать монету наибольшего возможного номинала.

Такой подход часто даёт короткое и быстрое решение. Но важное правило звучит так:

> Жадный выбор должен быть обоснован для конкретной задачи.

Разумный на вид выбор не всегда приводит к лучшему общему результату.

---

## 1. Общая схема

Во многих жадных алгоритмах действия выглядят так:

1. подготовить данные;
2. расположить варианты в нужном порядке;
3. последовательно просматривать их;
4. брать вариант, если он не нарушает ограничение;
5. не пересматривать сделанный выбор.

Обычно подготовка выполняется сортировкой:

```python
items.sort()
```

или сортировкой по выбранному полю:

```python
items.sort(key=lambda item: item[1])
```

Но сама сортировка ещё не доказывает правильность алгоритма. Нужно понимать, почему выбранный порядок ведёт к оптимальному ответу.

---

## 2. Максимальное количество объектов при ограничении

Пусть известна длительность нескольких задач. Нужно выполнить как можно больше задач за ограниченное время.

```python
durations = [40, 15, 25, 10, 30]
limit = 70
```

Чтобы увеличить количество выполненных задач, сначала выгодно брать самые короткие.

```python
durations.sort()

total_time = 0
count = 0

for duration in durations:
    if total_time + duration <= limit:
        total_time += duration
        count += 1

print(count)
print(total_time)
```

Результат:

```text
3
50
```

После сортировки длительности имеют вид:

```text
10, 15, 25, 30, 40
```

Выбраны первые три задачи. Четыре задачи выполнить невозможно, потому что сумма даже четырёх самых коротких длительностей равна `80`.

Здесь локальный выбор работает: замена короткой задачи на более длинную не освободит дополнительное время и не позволит увеличить количество выбранных задач.

---

## 3. Сохранение выбранных объектов

Часто требуется вывести не только количество, но и сами объекты.

```python
tasks = [
    ['задача 1', 40],
    ['задача 2', 15],
    ['задача 3', 25],
    ['задача 4', 10],
    ['задача 5', 30]
]

limit = 70

tasks.sort(key=lambda task: task[1])

selected = []
total_time = 0

for name, duration in tasks:
    if total_time + duration <= limit:
        selected.append(name)
        total_time += duration

print(selected)
print(total_time)
```

Результат:

```text
['задача 4', 'задача 2', 'задача 3']
50
```

Связанная информация хранится рядом: название задачи и её длительность сортируются вместе.

Если при равном количестве задач нужно дополнительно использовать как можно больше времени, одного жадного прохода может быть недостаточно. Все дополнительные требования нужно брать из условия.

---

## 4. Непересекающиеся мероприятия

Даны интервалы `[начало, конец]`. Нужно выбрать максимальное количество мероприятий, которые не пересекаются.

```python
events = [
    [1, 4],
    [3, 5],
    [0, 6],
    [5, 7],
    [8, 9],
    [5, 9]
]
```

Правильное жадное правило: выбирать мероприятие, которое заканчивается раньше остальных.

```python
events.sort(key=lambda event: event[1])

selected = []
last_end = None

for start, end in events:
    if last_end is None or start >= last_end:
        selected.append([start, end])
        last_end = end

print(selected)
```

Результат:

```text
[[1, 4], [5, 7], [8, 9]]
```

Раннее окончание оставляет как можно больше времени для следующих мероприятий.

Сортировать только по времени начала недостаточно. Рано начавшееся, но очень длинное мероприятие может перекрыть несколько коротких.

---

## 5. Почему выбор по окончанию работает

Пусть среди доступных мероприятий мы выбрали то, которое заканчивается раньше всех.

Любое другое мероприятие, которое можно поставить первым, заканчивается не раньше. Если заменить его нашим выбором, для следующих мероприятий останется не меньше свободного времени.

Поэтому первый жадный выбор не ухудшает возможное продолжение расписания. После него к оставшимся мероприятиям применяется то же правило.

Для школьных задач достаточно уметь объяснить эту мысль простыми словами. Формальное доказательство обычно не требуется, но причина правильности выбора должна быть понятна.

---

## 6. Жадный размен монет

Пусть доступны номиналы:

```python
coins = [10, 5, 2, 1]
amount = 28
```

Будем каждый раз брать наибольшую монету, не превышающую остаток.

```python
coins.sort(reverse=True)

selected = []
remainder = amount

for coin in coins:
    while coin <= remainder:
        selected.append(coin)
        remainder -= coin

print(selected)
print(len(selected))
```

Результат:

```text
[10, 10, 5, 2, 1]
5
```

Для этого набора номиналов жадный способ даёт минимальное количество монет.

Условие существования монеты `1` гарантирует, что любую целую положительную сумму можно набрать.

---

## 7. Контрпример для размена

Жадный размен работает не для любого набора номиналов.

```python
coins = [4, 3, 1]
amount = 6
```

Жадный алгоритм сначала берёт `4`, а затем две единицы:

```text
4 + 1 + 1
```

Получаются три монеты.

Но лучший вариант:

```text
3 + 3
```

содержит только две монеты.

Значит, правило «всегда бери наибольшую подходящую монету» для этого набора не гарантирует лучший ответ.

Этот пример показывает главное отличие жадного алгоритма от обычной эвристики: жадный выбор должен быть доказан или следовать из известного свойства задачи.

---

## 8. Проверка небольшого примера полным перебором

Для маленького набора данных предполагаемый жадный алгоритм можно проверить полным перебором.

```python
from itertools import combinations

durations = [40, 15, 25, 10, 30]
limit = 70

best_count = 0

for size in range(len(durations) + 1):
    for selected in combinations(durations, size):
        if sum(selected) <= limit:
            if size > best_count:
                best_count = size

print(best_count)
```

Результат:

```text
3
```

Результат совпадает с жадным решением.

Такая проверка не является доказательством для всех возможных данных, но помогает находить контрпримеры и ошибки на небольших тестах.

---

## 9. Как распознать жадную задачу

Перед применением жадного алгоритма задайте три вопроса.

### 1. Какой локальный выбор выполняется?

Например:

- самый короткий объект;
- самое раннее окончание;
- наибольший допустимый номинал.

### 2. Почему этот выбор не мешает будущим шагам?

Нужно объяснить, почему замена выбранного варианта на другой не улучшит итоговый ответ.

### 3. Можно ли построить контрпример?

Проверьте несколько маленьких наборов вручную или полным перебором.

Фразы «так кажется выгоднее» недостаточно. Если обоснования нет, задача может требовать полный перебор, поиск с возвратом или динамическое программирование.

---

## 10. Сравнение с другими подходами

### Полный перебор

Проверяет все варианты и позволяет получить точный ответ, но может работать слишком долго.

### Жадный алгоритм

Сразу делает один выбор и не возвращается назад. Обычно работает быстро, но только для задач с подходящим свойством.

### Динамическое программирование

Сохраняет лучшие результаты для промежуточных состояний. Оно часто применяется там, где простой жадный выбор не гарантирует оптимальный ответ.

Например, задача о размене произвольными номиналами может потребовать динамического программирования.

## 11. Работа с файлом

Пусть файл `data.txt` имеет формат:

```text
5 70
40 15 25 10 30
```

В первой строке записаны количество объектов и ограничение. Во второй — размеры или длительности объектов.

```python
with open('data.txt') as f:
    n, limit = map(int, f.readline().split())
    durations = list(map(int, f.readline().split()))

durations.sort()

total = 0
count = 0

for duration in durations:
    if total + duration <= limit:
        total += duration
        count += 1

print(count)
print(total)
```

Переменная `n` хранит ожидаемое количество элементов. В конкретной задаче формат файла и дополнительные условия могут отличаться.

---

## 12. Частые ошибки

### Ошибка 1. Выбрать очевидное правило без проверки

Самый большой, самый маленький или самый дорогой объект не обязательно ведёт к лучшему общему ответу.

### Ошибка 2. Сортировать не по тому полю

Для непересекающихся мероприятий нужен порядок по времени окончания:

```python
events.sort(key=lambda event: event[1])
```

### Ошибка 3. Потерять данные об объекте

Если требуется вывести выбранные объекты, сортируйте связанные поля вместе:

```python
[name, duration]
```

### Ошибка 4. Игнорировать дополнительные условия

Алгоритм, который максимизирует количество объектов, не обязательно одновременно максимизирует их стоимость или общий размер.

### Ошибка 5. Считать один удачный тест доказательством

Совпадение на нескольких примерах ещё не означает, что правило работает всегда.

```python
# Максимальное количество объектов при ограничении
items.sort()

total = 0
count = 0

for item in items:
    if total + item <= limit:
        total += item
        count += 1
```

```python
# Максимальное количество непересекающихся интервалов
events.sort(key=lambda event: event[1])

selected = []
last_end = None

for start, end in events:
    if last_end is None or start >= last_end:
        selected.append([start, end])
        last_end = end
```

Главное:

- жадный алгоритм не пересматривает сделанный выбор;
- данные часто предварительно сортируются;
- правило выбора зависит от конкретной задачи;
- разумный локальный выбор может оказаться неправильным;
- полезно искать контрпримеры на маленьких данных;
- при отсутствии обоснования следует рассмотреть полный перебор или динамическое программирование.
